# План разработки: квизы на лекции

Требования и план реализации фичи. Опирается на `docs/MULTI_TEACHER_PLAN.md` (права преподавателя, `state` с назначением) и `docs/COURSE_STORAGE_PLAN.md` (хранение файлов квизов).

## 1. Постановка задачи

Короткий квиз в конце лекции (около 5 минут) решает две задачи: автоматически отмечает присутствие и проверяет, слушали ли лекцию.

- Преподаватель показывает на проекторе QR-код; студенты заходят с телефонов и ждут начала.
- Преподаватель запускает квиз; все видят один и тот же вопрос, на ответ — заданное время (по умолчанию 20 секунд: мало, чтобы искать ответ или спрашивать LLM).
- По истечении времени показывается правильный ответ, затем следующий вопрос.
- Все вопросы — выбор одного из четырёх вариантов.
- Баллы сразу записываются в Google-таблицу курса.

Защита от участия без присутствия в аудитории (пересланный QR-код) не требуется.

Интеграция с Moodle не используется: синхронного режима в штатном Moodle нет, плагины и токен Web Services требуют прав администратора. Сервисы вроде Kahoot идентифицируют студента никнеймом; здесь студент уже связан с ФИО через GitHub-логин в таблице, и баллы пишутся туда же, куда оценки за лабораторные.

## 2. Что используется из существующего

- Вход через GitHub: `_exchange_code_for_username`, `/join/callback`, подписанный `state` с назначением (`MULTI_TEACHER_PLAN.md` §4.1) — здесь назначение `"student"`.
- Связь логина с ФИО: столбец `GitHub` (заголовок в первой строке листа группы), ФИО — `google.student-name-column`, данные со строки 3 (`docs/DEVELOPMENT.md` §2.2). Листы групп — все листы таблицы, кроме `google.info-sheet`.
- Столбец по короткому имени: `find_lab_column_in_grid` (`grading/sheets_client.py`).
- Десятичный разделитель: `get_decimal_separator`, `format_score`.
- Пакетная запись: `worksheet.batch_update` (как в `grading/bulk.py`).
- Права: `require_course_access`.
- Хранение файлов: `CourseStore` (`COURSE_STORAGE_PLAN.md` §4).
- Один процесс backend: состояние квиза в памяти, как у фоновых работ.

## 3. Файл квиза

### 3.1. Формат вопросов

Банк вопросов в markdown — формат `quiz_questions.md` из `course-maker` (`/course-maker quiz generate`). Пример:

```markdown
# Квиз по лекции 5
## Курс «Операционные системы»

**Время:** 5 минут

---

## Блок 1 — Процессы

### Вопрос 1.1 — Тип 1 (одиночный выбор), 25%
*Состояния процесса*

**Вариант А:** Какой системный вызов создаёт новый процесс в Linux?
- `fork()` ✓
- `exec()`
- `wait()`
- `kill()`

**Вариант Б:**
Чему равна сложность поиска в сбалансированном дереве из $n$ элементов?
- $O(1)$
- $O(\log n)$ ✓
- $O(n)$
- $O(n \log n)$
```

Правила разбора (по структуре, а не по словам: подписи «Вопрос», «Вариант», буквы вариантов — на языке курса):

- Первый заголовок `#` — название квиза по умолчанию. Всё до первого заголовка `###` (метаданные, таблица структуры, заголовки `##` блоков) не влияет на вопросы; заголовки `##` только группируют.
- Заголовок `###` — вопрос. Число с `%` в конце заголовка — вес вопроса.
- Строка сразу после заголовка, начинающаяся с курсива (`*…*`, возможно с хвостом вроде `⚠️ вопрос с подвохом`), — подзаголовок для преподавателя, студентам не показывается.
- Строка, начинающаяся с жирной метки с двоеточием (`**…:**`), открывает вариант вопроса. Текст вопроса — остаток этой строки и все строки до первого пункта списка (абзацы, блоки кода, формулы). Если меток нет, весь текст между заголовком и списком — единственный вариант.
- Пункты списка `- ` варианта — варианты ответа; правильный помечен ` ✓` в конце строки (метка убирается из текста).
- Текст — markdown: абзацы, `inline code`, блоки кода, формулы `$…$` и `$$…$$`. Сырой HTML не допускается.

Файл не принимается, если хотя бы в одном варианте: не ровно 4 варианта ответа, не ровно один ✓, пустой текст вопроса. Ошибка перечисляет все такие места: «Вопрос 1.2, Вариант Б: 5 вариантов ответа (нужно 4)».

### 3.2. Параметры квиза

Задаются в админке при создании и хранятся во front matter того же файла (один квиз — один файл):

```markdown
---
title: Квиз по лекции 5
short-name: К5            # столбец в таблице (вторая строка листа группы)
max-points: 2             # балл за весь квиз
seconds-per-question: 20
---
# Квиз по лекции 5
...
```

- `max-points` — число > 0, допускается дробное.
- `seconds-per-question` — от 5 до 300, по умолчанию 20.
- Front matter пишет сервер; загрузка файла, уже содержащего front matter, берёт из него значения по умолчанию для формы.

### 3.3. Хранение

`quizzes/{course_id}/{quiz_id}.md` в `CourseStore`: на сервере — приватный репозиторий конфигураций, локально — `courses/quizzes/` (добавляется в `.gitignore`). `quiz_id` — имя загруженного файла без расширения, приведённое к `[a-z0-9-]`; совпадение с существующим — 409. Сохранение — запись через хранилище с автором-преподавателем.

## 4. Баллы

- Вес вопроса — из заголовка; если веса заданы не у всех вопросов, все вопросы весят одинаково.
- Балл за вопрос: `max-points × вес / сумма весов`.
- Балл студента — сумма баллов за верные ответы, округление до 2 знаков, без лишних нулей (`1.5`, не `1.50`).
- Подключился к квизу и ничего не набрал — `0`. Не подключался — ячейка не заполняется.
- Если квиз завершён досрочно, незаданные вопросы дают 0; максимум не пересчитывается.

## 5. Ход квиза

### 5.1. Состояния запуска

```
lobby → question(0) → reveal(0) → question(1) → … → reveal(N-1) → finished
  └─────────────── cancel (из любого состояния до finished) ───────→ cancelled
                   finish (из любого состояния после lobby) ──────→ finished
```

- **lobby** — QR-код на проекторе, студенты подключаются.
- **question(i)** — вопрос показан, идёт отсчёт. Переход в `reveal(i)` — автоматически по дедлайну.
- **reveal(i)** — правильный ответ и распределение ответов; `next` — следующий вопрос или `finished` после последнего.
- **finished** — запускается запись в таблицу (§7).
- **cancelled** — ничего не записывается.

На курс одновременно — не больше одного незавершённого запуска (второй — 409 с `run_id` идущего).

### 5.2. Время

- Время решает сервер: `deadline = started_at + seconds-per-question`. Ответ принимается, если получен не позже `deadline + 1 с` (запас на сеть).
- Клиент получает оставшееся время в миллисекундах и только отображает отсчёт.
- Переход в `reveal` — задача `asyncio`, срабатывающая в `deadline + 1 с`.

### 5.3. Ответы

- Один ответ на вопрос; первый ответ окончательный (повторный — 409).
- Вариант вопроса (`А`/`Б`/…) выбирается случайно при открытии запуска и одинаков для всех.
- Порядок вариантов ответа перемешивается для каждого студента: `random.Random(f"{run_id}:{login}:{i}")` — при переподключении порядок тот же. Варианты ответа имеют идентификаторы (исходная позиция); клиент отправляет идентификатор.
- Правильный ответ не уходит на клиент до `reveal`.

## 6. Студент

### 6.1. Сессия

- Cookie `student_session` — подписанный `signer` JSON `{"login": ...}`, `httponly`, `samesite=lax`, `max_age` — `STUDENT_SESSION_MAX_AGE` (по умолчанию 180 дней). Вход нужен один раз за семестр.
- Выдаётся после входа через GitHub с назначением `"student"` в `state` (вместе с кодом запуска): `GET /quiz/login/start?code=…` → github.com → `/join/callback` → cookie → редирект на `{FRONTEND_URL}/q/{code}`.
- Cookie подтверждает только GitHub-логин; принадлежность к курсу проверяется по таблице при подключении к запуску.

### 6.2. Состав курса

- При открытии запуска сервер читает все листы групп (`get_all_values`, по одному запросу на лист) и строит словарь `логин (без учёта регистра) → (группа, строка, ФИО)`.
- Для каждого листа ищется столбец `short-name` квиза; листы без него перечисляются преподавателю предупреждением при открытии («в листах 4431, 4432 нет столбца «К5»: результаты этих групп не будут записаны»).
- Логина нет в словаре — словарь перечитывается, если прошлое чтение было больше 60 секунд назад (студент только что зарегистрировался); не нашёлся и после этого — отказ `NOT_IN_COURSE` со ссылкой на регистрацию в группе.
- Логин в нескольких листах — используется первый, в журнал — предупреждение.

### 6.3. Подключение

Студент может подключиться в любом состоянии до `finished` и отвечать на оставшиеся вопросы.

## 7. Запись в таблицу

- После перехода в `finished` — фоновая запись (`_start_background_job`, отдельный поток: gspread блокирующий).
- По каждому листу: свежий `get_all_values`, столбец квиза, строки участников этой группы. Записываются только пустые ячейки; непустые попадают в отчёт с текущим значением.
- Значение — `format_score` с разделителем таблицы, `value_input_option="USER_ENTERED"` (в таблице — число).
- Одна `batch_update` на лист.
- Итог запуска: по группам — записано, пропущено (непустая ячейка, нет столбца), ошибка. При ошибке — кнопка повтора в админке; повтор пишет только то, что не записано.

## 8. Журнал ответов

`{LOG_DIR}/quiz/{course_id}/{run_id}.jsonl`, одна строка на событие: открытие запуска (параметры, выбранные варианты вопросов), подключение (логин, группа), старт вопроса, ответ (логин, вопрос, идентификатор варианта, время получения, принят ли, верен ли), показ ответа, завершение, итог записи по группам. Токены и cookie не журналируются.

Перезапуск backend во время квиза теряет состояние запуска; журнал позволяет восстановить результаты вручную. Автоматическое продолжение после перезапуска не входит в объём.

## 9. Эндпоинты

Все эндпоинты квиза — `async def` и работают только с памятью; блокирующие вызовы (Sheets, запись в хранилище) — через поток. Состояние запуска меняется только в цикле событий под `asyncio.Lock`.

### 9.1. Админка (`require_course_access`)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/admin/courses/{c}/quizzes` | квизы курса: id, название, `short-name`, число вопросов, `max-points`, время |
| POST | `/admin/courses/{c}/quizzes` | multipart: файл + `title`, `short-name`, `max-points`, `seconds-per-question`; разбор и проверка (§3.1); 201 со сводкой |
| GET | `/admin/courses/{c}/quizzes/{q}` | разобранные вопросы с правильными ответами — предпросмотр |
| DELETE | `/admin/courses/{c}/quizzes/{q}` | удалить файл квиза |
| POST | `/admin/courses/{c}/quizzes/{q}/runs` | открыть запуск (`lobby`): состав курса, выбор вариантов, код; ответ — `run_id`, `code`, ссылка, предупреждения §6.2 |
| GET | `/admin/quiz-runs/{run_id}` | полное состояние для проектора |
| GET | `/admin/quiz-runs/{run_id}/events` | SSE для проектора |
| POST | `/admin/quiz-runs/{run_id}/start` | `lobby → question(0)` |
| POST | `/admin/quiz-runs/{run_id}/next` | `reveal(i) → question(i+1)` или `finished` |
| POST | `/admin/quiz-runs/{run_id}/finish` | досрочное завершение с записью |
| POST | `/admin/quiz-runs/{run_id}/cancel` | отмена без записи |
| POST | `/admin/quiz-runs/{run_id}/write-results` | повтор записи |

Запуск чужого курса — 404, как неизвестный `run_id`.

### 9.2. Студент

| Метод | Путь | Описание |
|---|---|---|
| GET | `/quiz/{code}` | название курса и квиза, состояние, вошёл ли студент; неизвестный или завершённый больше часа назад код — 404 «Квиз не найден или уже завершён» |
| GET | `/quiz/login/start?code=…` | вход через GitHub (§6.1) |
| POST | `/quiz/{code}/join` | подключение (`student_session`, §6.2); 401 `SESSION_REQUIRED`, 403 `NOT_IN_COURSE` |
| GET | `/quiz/{code}/events` | SSE состояния для участника |
| POST | `/quiz/{code}/answer` | `{"question": i, "option": id}`; 200, 409 `ALREADY_ANSWERED`, 410 `TOO_LATE`, 400 `WRONG_QUESTION` |

Код запуска — 6 символов из `abcdefghjkmnpqrstuvwxyz23456789`. Ссылка для QR — `{PUBLIC_BASE_URL или FRONTEND_URL}/q/{code}`, как у секретных ссылок.

### 9.3. SSE

- `text/event-stream`, заголовки `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
- Каждое событие — полный снимок состояния для получателя (не дельта), `id:` — номер версии состояния. Переподключение получает текущий снимок сразу.
- Комментарий-пинг каждые 15 секунд — соединение не закрывается обратным прокси по простою.
- Снимок студента: состояние, номер вопроса и их число, текст вопроса и варианты в его порядке, оставшееся время, его ответ; в `reveal` — правильный вариант и верен ли его ответ; в `finished` — его балл.
- Снимок проектора: то же без перемешивания (варианты A–D по порядку файла), число подключившихся и ответивших; в `reveal` — распределение ответов; в `finished` — сводка и итог записи.

### 9.4. Ограничение частоты запросов

Вся аудитория выходит в интернет через один адрес, поэтому лимиты по IP для квиза не подходят:

- `/quiz/{code}/join`, `/answer` — ключ лимита — логин из `student_session` (своя `key_func`), 30/minute на студента;
- `GET /quiz/{code}` — по IP, 1000/minute;
- SSE-эндпоинты — без лимита (одно долгое соединение).

## 10. Frontend

Новые зависимости (точные версии, `--legacy-peer-deps`): `react-markdown`, `remark-math`, `rehype-katex`, `katex`, `qrcode.react`. Рендер markdown без сырого HTML.

### 10.1. Студент: `/q/:code` (в первую очередь — телефон)

- Не вошёл — кнопка «Войти через GitHub» (переход на `/api/v1/quiz/login/start?code=…`).
- `NOT_IN_COURSE` — объяснение и ссылка на регистрацию.
- `lobby` — «Ждём начала».
- `question` — текст вопроса, четыре крупные кнопки, отсчёт; после ответа — «Ответ принят», кнопки неактивны.
- `reveal` — верно/неверно, правильный вариант.
- `finished` — балл.
- Потеря соединения — индикатор и автоматическое переподключение.

### 10.2. Админка

- Страница квизов курса `/admin/courses/:courseId/quizzes` (ссылка со страницы лабораторных): список, загрузка с формой параметров, предпросмотр вопросов с правильными ответами, удаление, «Запустить».
- Экран проектора `/admin/quiz-runs/:runId`, крупный шрифт:
  - `lobby` — QR-код, ссылка текстом, число подключившихся, кнопка «Начать»;
  - `question` — вопрос, варианты A–D, отсчёт, «ответили X из Y»;
  - `reveal` — правильный ответ, распределение, кнопка «Дальше»;
  - `finished` — участники, средний балл, итог записи по группам, повтор записи.
- «Завершить» и «Отменить» доступны всё время.

Переводы ru/en/zh.

## 11. Нагрузка

Ориентир — поток 200 студентов: 200 SSE-соединений и до 200 ответов за 20 секунд на один процесс. Эндпоинты квиза не занимают пул потоков синхронных эндпоинтов и не делают сетевых запросов на пути студента, кроме однократного чтения состава при открытии.

Скрипт `scripts/quiz-load-test.py` (asyncio + httpx): N фиктивных участников (вход подменяется подписанной `student_session` через `SECRET_KEY` тестового стенда), подключение, SSE, ответы со случайной задержкой; отчёт — доля принятых ответов и задержка доставки событий.

## 13. Не входит в объём

- Картинки в вопросах; другие типы вопросов.
- Бонус за скорость ответа.
- Защита от участия вне аудитории.
- Разные варианты вопроса разным студентам.
- Продолжение запуска после перезапуска backend.
- Несколько одновременных запусков на курс.
- История и аналитика запусков в интерфейсе (есть журнал §8).
- Moodle.

## 14. Тесты

Новые файлы `tests/test_quiz_parser.py`, `tests/test_quiz_scoring.py`, `tests/test_quiz_endpoints.py`:

- разбор: русские метки, текст вопроса на строке метки и на следующих строках, блок кода и формулы в тексте, курсивный подзаголовок не попадает в вопрос, вопрос без меток вариантов, веса; ошибки: 3 и 5 вариантов, два ✓, ни одного ✓, пустой текст — все места перечислены в одной ошибке; разбор реального банка из `course-maker`;
- front matter: запись и чтение, значения по умолчанию;
- баллы: веса, равные веса при неполных весах, округление, разделитель `,`, досрочное завершение;
- автомат состояний: допустимые и недопустимые переходы, второй запуск на курс — 409, отмена;
- время (часы подменяются): ответ до дедлайна, в запасе, после запаса; автоматический `reveal`;
- ответы: первый окончательный, неверный номер вопроса, ответ в `lobby`/`reveal`;
- перемешивание: детерминировано для студента и вопроса, различается между студентами; правильный ответ отсутствует в снимке до `reveal`;
- состав курса: логин без учёта регистра, повторное чтение после 60 с, `NOT_IN_COURSE`, лист без столбца квиза — предупреждение;
- запись: только пустые ячейки, отчёт о непустых, `0` подключившимся без верных ответов, неподключившиеся не записаны, повтор пишет только незаписанное;
- вход: `state` с назначением `student`, `student_session`, ключ лимита по логину;
- SSE: последовательность снимков для студента и проектора (`httpx.AsyncClient`, поток);
- права: запуск и квизы чужого курса — 404.
