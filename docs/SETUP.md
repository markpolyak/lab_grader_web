# Автозакрытие очереди на защиту (Google Apps Script)

Скрипт **необязателен**. Основное закрытие выполняет ленивая проверка в backend
(при первом обращении в новый день). Скрипт делает ту же операцию по расписанию,
поэтому при его работе backend находит нечего закрывать, а при его поломке
история всё равно пополняется. Включается и выключается галочкой в интерфейсе преподавателя.

## Что делает скрипт

Раз в сутки (около 01:30) для каждого листа `Очередь-YYYY-MM-DD` с датой **строго раньше сегодняшней**:

1. копирует строки в лист `История_очереди`; статус `ждёт` или пустой становится `не_дошло`;
2. проверяет, что все строки попали в историю;
3. только после этого удаляет лист очереди.

Чего скрипт **не** делает:

- не трогает сегодняшний и будущие листы;
- не создаёт, не пересоздаёт и не очищает листы очереди (это работа backend);
- не удаляет `_conflict`-листы и вообще любые листы с именем не по шаблону `Очередь-YYYY-MM-DD`;
- не удаляет ничего без копирования в историю;
- не имеет пунктов меню для ручного закрытия: очередь полностью автоматическая.

## Установка (один раз на таблицу курса)

1. Откройте таблицу курса, где хранятся листы очереди.
2. **Расширения → Apps Script**, удалите код в `Code.gs`, вставьте содержимое
   [`queue-apps-script/Code.gs`](../queue-apps-script/Code.gs).
3. Шестерёнка (Project Settings), включите **Show appsscript.json manifest file**,
   замените содержимое `appsscript.json` на
   [`queue-apps-script/appsscript.json`](../queue-apps-script/appsscript.json)
   (`timeZone` — `Europe/Moscow`).
4. Дайте таблице доступ редактора сервисному аккаунту backend (адрес `client_email` из файла credentials).
5. Вернитесь в таблицу, обновите страницу. В меню **Очередь → Включить автозакрытие**,
   подтвердите доступ Google (Review permissions → аккаунт → Allow).
6. Необязательно: **Очередь → Защитить историю**. Лист истории станет доступен для правки только
   владельцу и сервисному аккаунту (см. ниже).

До включения галочки `script_enabled` в интерфейсе преподавателя скрипт не закрывает листы.
После установки включите эту галочку, чтобы разрешить ежедневное автозакрытие.
Если скрипт не отвечает, интерфейс покажет предупреждение, а закрывать продолжит backend.

## Меню «Очередь»

| Пункт | Действие |
|---|---|
| Включить автозакрытие | создаёт ежедневный триггер, делает первый прогон |
| Выключить автозакрытие | удаляет триггер |
| Статус автозакрытия | показывает значения служебного листа |
| Защитить историю | ограничивает правку листа `История_очереди` |

Закрыть день вручную из меню нельзя намеренно.

## Служебный лист `autoclose_status`

Создаётся автоматически. Пары «ключ — значение».

| Ключ | Кто пишет | Смысл |
|---|---|---|
| `installed_at` | скрипт | когда включено автозакрытие (пусто — выключено) |
| `script_version` | скрипт | версия `Code.gs`; backend сравнивает с ожидаемой и показывает «обновите скрипт» |
| `last_run` | скрипт | последний запуск |
| `last_success` | скрипт | последний запуск без ошибок |
| `last_error` | скрипт | ошибки последнего запуска (пусто — нет) |
| `last_rows_copied` | скрипт | сколько строк скопировано за последний запуск |
| `copy_lease` | скрипт и backend | кто сейчас копирует (`владелец\|время истечения`) |
| `script_enabled` | backend | `TRUE`/`FALSE` — галочка в интерфейсе; при `FALSE` скрипт ничего не делает |
| `utc_offset` | backend | например `+03:00`, из `timezone` в конфиге курса; определяет, что такое «сегодня» |
| `service_account_email` | backend | нужен для «Защитить историю» |

Значения хранятся текстом, чтобы Таблицы не превращали даты в числа.

## Структура листов

### `Очередь-YYYY-MM-DD` (создаёт backend)

| ПОЗИЦИЯ | ГРУППА | ФИО | ЛР | Пар№ | Статус |
|---|---|---|---|---|---|
| 1 | 4431 | Иванов И.И. | ЛР1 | 2 | ждёт |

Статусы: `ждёт`, `сдал`, `не_сдал`, `нет`, `отозван`. Если в проекте есть статус «вызван»,
добавьте его в константу `NOT_FINISHED` в `Code.gs`, иначе он при закрытии останется как есть.

### `История_очереди` (только добавление)

| Дата | ПОЗИЦИЯ | ГРУППА | ФИО | ЛР | Пар№ | Статус |
|---|---|---|---|---|---|---|
| 2026-11-08 | 1 | 4431 | Иванов И.И. | ЛР1 | 2 | сдал |
| 2026-11-08 | 2 | 4431 | Петров П.П. | ЛР1 | 2 | не_дошло |

- Ключ строки: `Дата + ПОЗИЦИЯ + ГРУППА + ФИО + ЛР`. Повторная запись студента на ту же работу
  в тот же день получает другую позицию и сохраняется отдельной строкой.
- Колонка «Дата» хранится текстом.
- Скрипт только добавляет строки. Чтобы остальные не могли их менять, выполните «Защитить историю».

## Как скрипт и backend не мешают друг другу

Обе стороны выполняют одну и ту же идемпотентную операцию с одним форматом строк:

1. найти листы очереди с датой раньше сегодняшней, если их нет — ничего не делать;
2. взять аренду `copy_lease` (если чужая и не истекла — уйти);
3. дописать в историю только строки, ключей которых там ещё нет;
4. проверить, что все строки очереди есть в истории;
5. удалить лист очереди, только если он не менялся с момента чтения.

Аренда не атомарна (у Таблиц нет compare-and-set), поэтому от дублей в первую очередь защищает ключ строки.
Ночью записи в очередь невозможны, так что на практике запуски не пересекаются.

## Проверка после установки

1. В таблице есть лист `Очередь-<вчерашняя дата>` с парой строк (создайте вручную для теста).
2. В редакторе Apps Script выберите функцию `closeDay` и нажмите **Run**
   (из меню закрыть день нельзя, но из редактора можно).
3. Лист вчерашней даты исчез, строки появились в `История_очереди`, сегодняшний лист на месте.
4. В `autoclose_status` заполнены `last_run`, `last_success`, пустой `last_error`.
5. В **Triggers** (часы слева) виден триггер `closeDay`.

## Решение проблем

**Меню не появилось.** Обновите страницу, проверьте наличие `onOpen` в `Code.gs`.

**Лист не закрылся.** Откройте `autoclose_status`:
- `last_error` не пуст: прочитайте, на каком листе ошибка (нет доступа, неожиданный формат);
- `last_run` старый: триггера нет или слетел доступ, повторите «Включить автозакрытие»;
- в `script_enabled` стоит `FALSE`: галочка снята в интерфейсе;
- в `copy_lease` чужая запись с будущим временем: идёт закрытие backend, подождите несколько минут.

**«Лист изменился во время закрытия».** В лист прошлой даты кто-то писал во время копирования.
Лист не удалён, следующий запуск добавит недостающие строки и закроет его.

**Появились `_conflict`-листы.** Скрипт их игнорирует, они не попадают в историю. Причина в backend
(одновременное создание листа), удалять такие листы стоит вручную после проверки, нет ли в них данных.

**Обновление скрипта.** При изменении `Code.gs` в репозитории вставьте новую версию в каждую таблицу вручную.
Backend сравнит `script_version` с ожидаемой и подскажет, где она отстаёт.
