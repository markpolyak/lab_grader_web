# План разработки: секретные ссылки на получение репозитория и контрольные работы

Продолжение задач #46 (`docs/REPO_GENERATION_PLAN.md`) и #54 (`docs/TEAM_ASSIGNMENTS_PLAN.md`).
Требования и план реализации фичи.

## 1. Постановка задачи

Сейчас ссылка `/join/{course_id}/{lab_id}` существует для каждой лабы, у которой настроен
`template-repo`, и работает с момента деплоя конфига. Помимо лабораторных, в курсе есть
контрольная работа, для которой этого недостаточно:

- до публикации ссылки преподавателем студенты не должны видеть контрольную ни в интерфейсе,
  ни через перебор адресов;
- ссылка должна быть неугадываемой, как в GitHub Classroom, а не отличаться от соседней
  номером лабы;
- механика после перехода по ссылке та же, что у лабораторной: создаётся форк репозитория с
  заданием, вариант генерируется автоматически в репозитории студента после первого коммита.

Решение оформляется не как отдельная сущность «контрольная», а как два свойства лабы: секретная
ссылка и окно доступности. Контрольная — это лаба с обоими свойствами.

## 2. Что раскрывает лабу сейчас

1. **Перебор адресов.** `find_lab_config` (`main.py`) находит лабу по ключу конфига (`7`), по
   `short-name` (`Тест / КР`) и по произвольной строке с числом (`lab7`). `course_id` публичен
   (`GET /courses`). `GET /join/{course_id}/{lab_id}` отвечает 200 с названием курса и лабы для
   существующей лабы и 404 для несуществующей — это оракул, по которому перебор подтверждается.
2. **Проверка работ.** `POST /courses/{c}/groups/{g}/labs/{lab_id}/grade` резолвит лабу так же и
   по тексту ошибки отличает известную лабу от неизвестной.
3. **Список лаб студента.** `GET /courses/{c}/groups/{g}/labs` — пересечение `short-name` из
   конфига с заголовками второй строки листа группы. Не создавать столбец до контрольной можно и
   сейчас, но столбец нужен для выставления оценки, а `/join` это всё равно не закрывает.
4. **Публичный репозиторий проекта.** `courses/*.yaml` отслеживаются в git, а репозиторий
   `markpolyak/lab_grader_web` публичный (`docs/DEPLOYMENT.md` предписывает коммитить конфиги).
   Конфигурация контрольной — `github-prefix`, `short-name`, имя `template-repo` — видна на
   GitHub в любом случае.

Из пункта 4 следует определение секретности, принятое в этом плане: **секретна не сама
контрольная, а возможность получить репозиторий с заданием до публикации ссылки**. Содержимое
задания защищено приватностью репозитория-шаблона, и именно ранний доступ к нему даёт студенту
фору. Видимость конфигурации в публичном репозитории — принятое допущение, отдельно закрывать её
не требуется.

## 3. Архитектурное решение

### 3.1. Токен вычисляется, а не хранится

```
token = base32( HMAC-SHA256( SECRET_KEY, f"{course_id}\n{lab_key}\n{revision}" )[:16] )
```

- 128 бит, 26 символов в нижнем регистре без символов-заполнителей. Перебор невозможен.
- `SECRET_KEY` уже есть в окружении и используется для подписи `admin_session` и OAuth `state`
  (`main.py:143`).
- `lab_key` — канонический ключ лабы в YAML, как в `docs/TEAM_ASSIGNMENTS_PLAN.md` §7.2.
- Сравнение только через `secrets.compare_digest`.

Что это даёт:

- в git не попадает ничего секретного: в конфиге видны лишь `link: secret` и номер ревизии;
- не появляется нового хранилища — проект сознательно обходится без БД;
- ссылка отзывается увеличением `revision`: старая перестаёт работать немедленно;
- сервер может в любой момент восстановить ссылку по конфигу — она нужна и админке, и редиректу
  на страницу результата после OAuth.

Цена решения: смена `SECRET_KEY` инвалидирует все секретные ссылки (и сбрасывает админские сессии,
как и сейчас). Это фиксируется в `docs/DEPLOYMENT.md`.

### 3.2. Отклонённые варианты

**Случайный токен в конфиге курса.** Публикуется вместе с конфигом в публичном репозитории.

**Случайный токен в файле вне git (volume).** Работает, но вводит состояние на сервере, которое
нужно бэкапить и которое расходится между окружениями; единственное преимущество перед HMAC —
независимость от `SECRET_KEY`.

**Приватный репозиторий проекта или вынос конфигов из git.** Закрывал бы и видимость
конфигурации, но это несоразмерно задаче — см. определение секретности в §2.

**Отдельная сущность «контрольная» в конфиге.** Потребовала бы дублирования всей логики лабы
(проверка работ, штрафы, баллы, MOSS) ради одного отличия — способа выдачи ссылки.

### 3.3. Окно доступности

Окно задаётся в конфиге заранее, чтобы в аудитории не требовалось никаких действий:

- `opens-at` — момент публикации: ссылка начинает работать, лаба появляется в списке у студента;
- `closes-at` — необязательно. Не задано — ссылка действует бессрочно с момента открытия.

Разбор значений — существующим `grading.sheets_client.parse_deadline(value, timezone_str)`:
он уже принимает наивные даты и применяет к ним `timezone` курса (формат `UTC+3`).

**Отсутствие `opens-at` у секретной лабы означает «ещё не открыта»**, а не «открыта сразу»: иначе
контрольная, закоммиченная в конфиг заранее, заработала бы в момент деплоя. Для лаб с публичной
ссылкой отсутствие окна по-прежнему означает «открыта», поэтому поведение существующих ссылок не
меняется.

### 3.4. Допущение о группах

Окно задаётся на лабу целиком, поэтому модель верна при условии, что **все группы пишут
контрольную одновременно** (подтверждено при обсуждении). Если группы когда-нибудь будут писать в
разное время, пересылка ссылки между группами станет дырой, и потребуется окно на группу — а это
знание группы студента в сценарии `/join`, которого там сейчас нет (см. §11).

## 4. Конфигурация курса

Новая секция в `labs.*`:

```yaml
labs:
  "7":
    github-prefix: kr1
    short-name: "Тест / КР"
    template-repo: suai-os-2026/kr1-template
    repo-provisioning: fork
    ignore-task-id: true
    join:
      link: secret                     # public (по умолчанию) | secret
      opens-at: "2026-10-15 10:00"     # момент публикации
      closes-at: "2026-10-15 11:30"    # необязательно
      revision: 1                      # увеличить, чтобы отозвать ссылку
```

### `join.link`
**Тип:** `string`, **по умолчанию:** `public`
**Описание:** `secret` переводит лабу на неугадываемую ссылку `/j/{token}`. Адрес
`/join/{course_id}/{lab_id}` для такой лабы перестаёт работать навсегда, а не только до публикации.

### `join.opens-at`
**Тип:** `string` (дата и время; наивное значение трактуется в `timezone` курса)
**Описание:** Момент публикации. До него ссылка сообщает, что работа ещё не открыта, а лаба не
показывается в списке студента. Для `link: secret` отсутствие поля означает «не открыта».

### `join.closes-at`
**Тип:** `string`, **необязательно**
**Описание:** Момент закрытия приёма. После него новые репозитории не создаются, но студент с уже
созданным репозиторием может восстановить доступ по той же ссылке. Пустое или отсутствующее
значение — ссылка бессрочная.

### `join.revision`
**Тип:** `int`, **по умолчанию:** `1`
**Описание:** Входит в вычисление токена. Увеличение немедленно отзывает разосланную ссылку.

Проверки конфигурации (по образцу `warn_about_team_labs`, ошибки — в лог при старте, а на запрос
`/j/{token}` и `/join/...` отвечаем понятной ошибкой конфигурации, не 500):

- `link` вне `{public, secret}`;
- `opens-at`/`closes-at` не разбираются или `closes-at` раньше `opens-at`;
- `revision` не целое ≥ 1;
- **`team` вместе с `link: secret`** — в этой итерации не поддерживается (§11), ошибка конфигурации.

Для контрольной, где вариант генерируется в репозитории после первого коммита, нужен
`ignore-task-id: true`: иначе проверка сверит TASKID с номером студента в таблице.

## 5. Состояния

| Момент | `/j/{token}` | `/join/{course}/{lab}` | Список лаб студента | Проверка работ |
|---|---|---|---|---|
| до `opens-at` | «работа ещё не открыта», с указанием времени открытия | 404, как у несуществующей лабы | не показывается | публичный эндпоинт — 404, как у несуществующей; массовая из админки работает |
| `opens-at` … `closes-at` | создаёт репозиторий, чинит доступ | 404 | показывается | обе |
| после `closes-at` | новые репозитории не создаются; доступ к уже созданному чинится | 404 | показывается | обе |

Лаба остаётся в списке и после `closes-at`: проверять работу студенты будут как раз после
окончания контрольной.

## 6. Резолв токена

Модуль `grading/join_links.py` (по образцу `grading/teams.py` — без FastAPI и Google Sheets):

```python
TOKEN_RE = re.compile(r"^[a-z2-7]{26}$")

def is_secret_lab(lab_config: dict) -> bool
def compute_token(secret_key: str, course_id: str, lab_key: str, revision: int) -> str
def parse_window(lab_config: dict, timezone_str: str | None) -> JoinWindow   # opens_at, closes_at
def resolve_token(secret_key: str, token: str) -> tuple[str, str] | None     # (course_id, lab_key)
```

`resolve_token` перебирает курсы из `index.yaml`, для каждой лабы с `link: secret` вычисляет токен
и сравнивает через `compare_digest`. Лаб в проекте десятки, поэтому индекса не требуется; функция
читает те же файлы, что и существующий `GET /courses`. Формат токена проверяется регулярным
выражением до перебора, чтобы мусорные строки отсеивались сразу.

`JoinWindow` отвечает на три вопроса: открыта ли ссылка сейчас, закрыт ли приём, показывать ли
лабу в списке. Время берётся один раз на запрос.

## 7. Эндпоинты

### 7.1. Новые

Префикс `/j/` выбран отдельным намеренно: `/join/{token}` конфликтовал бы с
`/join/{course_id}/{lab_id}` и `/join/callback`.

| Метод и путь | Назначение | Лимит |
|---|---|---|
| `GET /j/{token}` | Публичная информация для лендинга: название курса и работы, состояние окна, время открытия | `30/minute` |
| `GET /j/{token}/start` | Проверяет окно и начинает GitHub OAuth (тот же flow, что и `/join/.../start`) | `20/minute` |

Колбэк остаётся один — `GET /join/callback`. Токен в `state` не кладётся: сервер знает
`course_id` и `lab_key` из подписанного `state` и вычисляет токен заново для редиректа на
страницу результата `/j/{token}?status=...`.

### 7.2. Изменения в существующих

| Эндпоинт | Изменение |
|---|---|
| `GET /join/{course_id}/{lab_id}` и `/start` | Для лабы с `link: secret` — 404 с тем же телом, что у несуществующей лабы. Отличить одно от другого снаружи нельзя |
| `GET /join/callback` | Перед провижинингом проверяет окно: после `closes-at` репозиторий не создаётся (см. §8). Редирект на результат ведёт на `/j/{token}` для секретной лабы и на `/join/{c}/{l}` для обычной |
| `GET /courses/{c}/groups/{g}/labs` | Лабы, не достигшие `opens-at`, из списка исключаются |
| `POST /courses/{c}/groups/{g}/labs/{lab_id}/grade` | Для лабы, не достигшей `opens-at`, — 404 «Лабораторная работа не найдена» |
| `GET /admin/courses/{course_id}/labs` | Добавляются `join_link` (готовый URL), `join_state` (`not_open`/`open`/`closed`), `opens_at`, `closes_at` |
| Массовая проверка (`/admin/.../bulk-grade`) | Не меняется: окно на неё не влияет |

Публичные пути резолвят лабу через новую обёртку `find_public_lab_config`, которая пропускает
секретные лабы и не достигшие `opens-at`. Прямой `find_lab_config` остаётся для админских путей,
`/j/{token}` и массовой проверки.

### 7.3. Коды ошибок

| Код | HTTP | Причина |
|---|---|---|
| `LINK_NOT_FOUND` | 404 | Токен не совпал ни с одной лабой, отозван (`revision`) или испорчен |
| `JOIN_NOT_OPEN` | 403 | Ещё не наступил `opens-at`; в ответе — время открытия |
| `JOIN_CLOSED` | 403 | Приём закрыт, а репозитория у студента нет |
| `LAB_MISCONFIGURED` | 400 | Секция `join` не разбирается |

Коды `ProvisionResult.error_code` пробрасываются как есть — фронтенд уже умеет их переводить.

## 8. Закрытие приёма и провижининг

После `closes-at` студент с уже созданным репозиторием должен сохранить возможность починить
доступ (протухшее приглашение), а новый репозиторий создаваться не должен.

`RepoProvisioner.provision` получает параметр `create: bool = True`. При `create=False`
`_ensure_repo_created` не создаёт отсутствующий репозиторий, а возвращает ошибку
`JOIN_CLOSED`; если репозиторий есть, выполняется обычная проверка и починка доступа. Значение по
умолчанию сохраняет поведение индивидуальных и командных лаб без изменений.

## 9. Админка

На странице `/admin/courses/{course_id}/labs` для лабы с `link: secret`:

- готовая ссылка с кнопкой копирования (её видит только авторизованный администратор);
- состояние: «откроется 15.10.2026 10:00», «открыта до 11:30», «приём закрыт»;
- подсказка, что отзыв ссылки — это увеличение `join.revision` в конфиге курса.

## 10. Frontend

- Маршрут `/j/:token` → существующий компонент `JoinLab` в режиме секретной ссылки: данные
  берутся из `GET /j/{token}`, кнопка входа ведёт на `/j/{token}/start`, результат возвращается
  на тот же адрес. Маршрут `/join/:courseId/:labId` продолжает работать для обычных лаб.
- Новые состояния экрана: «работа ещё не открыта» (с временем открытия) и «приём закрыт» (с
  пояснением, что доступ к уже созданному репозиторию можно восстановить).
- Новые ключи в `frontend/courses-front/src/locales/{en,ru,zh}/` для этих состояний и кодов §7.3.
- На странице секретной ссылки выставляется `Referrer-Policy: no-referrer`, чтобы токен не уходил
  в заголовке `Referer` при переходе на github.com.

## 11. Не входит в объём

- **Командные лабы с секретной ссылкой.** Командный сценарий адресуется парой course/lab: три
  эндпоинта `/join/{c}/{l}/teams…`, сверка cookie `join_session` с путём, маршрут экрана выбора
  команды. Перевод их на адресацию токеном — отдельная задача; пока сочетание `team` +
  `link: secret` отвергается как ошибка конфигурации.
- **Перевод существующих лабораторных на секретные ссылки.** Механизм общий, поэтому это правка
  конфига (`link: secret`), а не разработка: уже созданные репозитории не затрагиваются, но
  разосланная ранее ссылка перестанет работать. Решение принимается отдельно.
- **Окно на группу.** Требует знания группы студента в сценарии `/join` (поиск GitHub-логина по
  листам таблицы) и делает регистрацию обязательной до получения репозитория. Не требуется, пока
  все группы пишут одновременно (§3.4).
- **Одноразовые и персональные ссылки.** Ссылка общая для всех студентов, как и сейчас.
- **Хранение факта «ссылка открыта» на сервере.** Состояние выводится из конфига и текущего
  времени.

## 12. Тесты

Новый файл `tests/test_join_links.py`:

- `compute_token`: детерминированность, зависимость от `course_id`, `lab_key`, `revision` и
  `SECRET_KEY`; формат и длина;
- `resolve_token`: находит лабу; не находит после смены `revision`; не находит для лабы с
  `link: public`; отвергает мусор по `TOKEN_RE` без перебора;
- `parse_window`: наивное время трактуется в `timezone` курса; отсутствие `closes-at` — бессрочно;
  отсутствие `opens-at` — закрыто для секретной лабы и открыто для обычной; `closes-at` раньше
  `opens-at` — ошибка конфигурации;
- состояния окна на границах (ровно `opens-at`, ровно `closes-at`).

Дополнения к существующим файлам:

- `tests/test_join_endpoints.py`: `/join/{c}/{l}` для секретной лабы отвечает тем же 404, что и
  несуществующая лаба (сравнение тела ответа); `/j/{token}` до открытия — `JOIN_NOT_OPEN`; после
  закрытия создание репозитория отклоняется, а починка доступа проходит; редирект результата ведёт
  на `/j/{token}`;
- `tests/test_repo_provisioning.py`: `create=False` не создаёт отсутствующий репозиторий и чинит
  доступ к существующему;
- `tests/test_admin_endpoints.py`: админский список лаб отдаёт ссылку и состояние окна;
- `tests/test_lab_resolution.py`: `find_public_lab_config` пропускает секретные и неоткрытые лабы,
  `find_lab_config` продолжает их находить.
