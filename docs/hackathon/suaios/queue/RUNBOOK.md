# Запуск и эксплуатация

[Главная](../../../../README.md) · [Документация](../../../README.md) · [Песочница](SANDBOX.md) · [Проверки](VERIFICATION.md)

## Выбрать режим

| Цель | Как запустить | Где открыть |
|---|---|---|
| Показать весь сценарий без ключей | `./start-sandbox` | [Управление песочницей](http://localhost:8010/sandbox), [вход преподавателя](http://localhost:5180/admin) |
| Проверить настоящие публичные данные | `./start-main` | [Преподаватель](http://localhost:5173/admin), пароль печатается в терминале |
| Работать со своим курсом, репозиториями и таблицей | Настроить окружение по разделу ниже | [Сервис](http://localhost:5173), [панель очередей](http://localhost:5173/admin/queue) |

Первые два режима запускают backend и frontend одной командой. Собственный рабочий сервис использует обычный `main:app` и свои ключи. Docker не требуется. Состояния режимов лежат в разных базах.

## Подготовка окружения

Из корня репозитория, с Python 3.12 и Node.js 20+:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
npm ci --prefix frontend/courses-front --legacy-peer-deps
```

Если используется uv: `uv venv --python 3.12 .venv`, затем та же установка зависимостей. Для повторного запуска установка не нужна. Полный маршрут установки доступов описан в [DEVELOPMENT.md](../../../DEVELOPMENT.md).

## Рабочий сервис на своём курсе

### 1. Подготовить доступы

1. Скопировать `.env.example` в `.env`, если своего `.env` ещё нет.
2. Указать `GITHUB_TOKEN` с доступом к нужным репозиториям. Сервис ищет CI по конфигурации лабораторной.
3. Создать собственный Google service account, открыть ему доступ к своей таблице и указать локальный путь JSON-ключа в `CREDENTIALS_FILE`.
4. Задать собственные `ADMIN_LOGIN`, `ADMIN_PASSWORD`, случайный `SECRET_KEY` и `FRONTEND_URL=http://localhost:5173`.
5. Сохранить `QUEUE_DB_PATH=data/queue.sqlite3` и `QUEUE_WORKER_ENABLED=1`.

Здесь нужны собственные доступы преподавателя. Публичный доступ к чужой таблице позволяет читать её на стенде, но не регистрировать в ней работы. `.env` и JSON-ключ остаются локально.

### 2. Включить очередь в курсе

В конфигурации своего курса внутри `course`:

```yaml
queue:
  enabled: true
  timezone: Europe/Moscow
  semester_week_anchor: '2026-08-31'
  required_labs: ['1', '2', '3']
  deadline_row: 1
```

Поменять якорь семестра и ключи работ на значения своего курса. Ключи должны существовать в `labs`; порядок задаёт последовательность работ. При необходимости `required_labs_by_group` задаёт её отдельно для групп. Курс должен присутствовать в `courses/index.yaml` по [правилам конфигурации](../../../COURSE_CONFIG.md).

Дедлайны читаются из строки над столбцами лабораторных; преподаватель может исправить их в панели. «Без дедлайна» — явное состояние, отличное от ошибки чтения. При недоступном сроке без ручного значения сервер включает случайный режим. При известных сроках доступен −1 и ручной переключатель на случайный режим.

### 3. Запустить

Терминал 1, из корня репозитория:

```bash
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Терминал 2, тоже из корня:

```bash
VITE_API_BASE_URL=http://localhost:8000 VITE_PROXY_TARGET=http://127.0.0.1:8000 npm --prefix frontend/courses-front run dev -- --host localhost --port 5173 --strictPort
```

Открыть [вход преподавателя](http://localhost:5173/admin) с данными своего `.env`, выбрать предмет и «Очередь защит». API-справочник: [http://localhost:8000/docs](http://localhost:8000/docs).

Для первого рабочего развёртывания используется один процесс backend. Серверное размещение, HTTPS и собственные контейнеры описаны в [DEPLOYMENT.md](../../../DEPLOYMENT.md). Vite dev server предназначен для локального просмотра, не для публичного хостинга.

## Студент

1. Открыть страницу курса `/course/<course_id>`.
2. Выбрать группу, затем лабораторную.
3. Ввести ФИО и GitHub в прежней форме и запустить регистрацию/проверку.
4. Открыть вкладку «Список на занятие».
5. После допуска нажать «Да, я приду». По умолчанию ответ «Не придёт», строка зачёркнута. Ответ можно изменить до начала пары без повторного запуска проверки.

Целевая работа — первая готовая после последней защищённой. `vv / пусто / v` и `v / vv / v` выбирают третью работу. Студент без допуска имеет предварительное место, но не может подтвердить участие. Номер работы в строке списка не показывается.

С начала пары до окончания + 10 минут студент видит текущие списки, порядок и результаты без кнопок преподавателя. Затем открывается следующее назначенное занятие группы. На новую пару участие нужно подтвердить заново.

## Преподаватель

- До пары: выбрать предмет, группу, занятие, проверить дедлайны и состав.
- Во время пары: вызвать студента, отметить «Сдал», «Не сдал» или «Не пришёл». Несколько студентов могут защищаться одновременно.
- После неудачи: автоматический повтор добавляет новую попытку в конец, если включён в настройках.
- Для отсутствующего с допуском: «Пришёл» добавляет в конец нового круга.
- После ошибочного действия: «Отменить» в уведомлении в пределах настроенных 1–10 секунд. Сервер проверяет последующие изменения и подтверждение таблицей.
- После пары: посмотреть итоги и историю выбранного занятия. До начала пары статистика защит неактивна.

Полная логика кнопок и повторов: [ROUNDS.md](ROUNDS.md). Модуль очереди не изменяет оценки Google Sheets; преподаватель ставит `vv` прежним способом.

## Расписание и другие вузы

Во вкладке «Расписание» выбрать группу или «Все» для обзора. Для очереди и дедлайнов выбирается конкретная группа. Источник и вуз задаются в настройках группы курса.

- **ГУАП:** числовой ID группы, точное имя предмета, при необходимости тип занятия/преподаватель и якорь чередования недель. Адаптер импортирует занятия на восемь недель вперёд в пределах семестра, обновление — раз в час.
- **Другой вуз:** ручные занятия либо JSON-импорт. Формат и ключи: [ADR-0003](../../../adr/0003-schedule-adapters.md).
- **Ручные изменения:** дополнительная пара, перенос, отмена и восстановление. Ручная правка важнее обновления источника. Перенос сохраняет `session_id` и ответы; новое время начала не может быть в прошлом, конец рассчитывается через 90 минут.

Если защита на занятии уже началась, историю не переносят: назначается дополнительная пара. Общий `teacher_key` связывает занятия одного преподавателя; каждый результат относится к конкретному студенту и занятию.

## После пары и при сбое

Через 10 минут после окончания фоновая задача читает таблицу и подтверждает `vv`. Незавершённые попытки можно принимать до местной полуночи. В 00:00 задача повторно читает таблицу и закрывает оставшиеся попытки в историю. Если пара заканчивается незадолго до полуночи, выполняется ночная сверка. Задания и повторы после ошибки хранятся в SQLite.

При недоступности Sheets сервер показывает сохранённый список с пометкой устаревших данных и блокирует изменение посещения до обновления допуска. История и локальные действия преподавателя остаются доступны. При сбое расписания импортированные занятия сохраняются; исчезновение карточки с сайта не считается ручной отменой.

## База и резервная копия

`QUEUE_DB_PATH` задаёт постоянный путь. Backend нужны права записи в каталог базы, WAL и SHM. Миграции 001–008 применяются автоматически; `schema.sql` служит справочным снимком, его не нужно вручную накатывать на базу приложения.

Резервная копия работающей базы через SQLite Backup API:

```bash
.venv/bin/python - <<'PYCODE'
import os
import sqlite3
from datetime import datetime
from pathlib import Path
from dotenv import load_dotenv
load_dotenv('.env')
source = Path(os.getenv('QUEUE_DB_PATH', 'data/queue.sqlite3')).resolve()
if not source.is_file():
    raise SystemExit(f'База не найдена: {source}')
target = source.with_name(f'{source.stem}-{datetime.now():%Y%m%d-%H%M%S}.backup.sqlite3')
with sqlite3.connect(f'{source.as_uri()}?mode=ro', uri=True) as src, sqlite3.connect(target) as dst:
    src.backup(dst)
print(target)
PYCODE
```

Для восстановления остановить backend, поместить копию в новый пустой каталог и задать её путь в `QUEUE_DB_PATH`. Это исключает смешивание копии со старыми WAL/SHM. Не удалять постоянный том через `docker compose down -v`. В Docker используется каталог `/app/data` с постоянным томом; пример Compose нужно направить на собственные образы из этой версии.

## Частые вопросы

| Симптом | Что сделать |
|---|---|
| Порт занят | Остановить прежний процесс через Ctrl+C; для готовых запусков можно выбрать `--port` и `--frontend-port` |
| Вход песочницы не работает | Использовать 5180 и 8010 одного запуска; пароль `sandbox123`, логин `sandbox` |
| Вход стенда не работает | Логин `local`, случайный пароль из текущего терминала `start-main` |
| Вкладка регистрации недоступна на стенде | Так устроен публичный профиль; полный сценарий — в песочнице или собственном сервисе |
| Случайный режим нельзя выключить | Проверить получение всех требуемых дедлайнов или задать их вручную |
| Студент зачёркнут | На это занятие нет подтверждения «Приду» либо нет допуска |
