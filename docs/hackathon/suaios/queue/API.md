# Подключение API очереди

Очередь включается отдельно для курса. Существующие курсы без `queue.enabled` сохраняют прежнее поведение.

```yaml
queue:
  enabled: true
  timezone: Europe/Moscow
  semester_week_anchor: '2026-08-31'
  required_labs: ['1', '2']
  random: false
  deadline_row: 1
  deadlines:
    '1': null  # явно без дедлайна; это не ошибка чтения
    '2': '2026-11-30'
```

Настройки размещаются внутри блока `course`, рядом с `labs` и `google`. `required_labs` определяет порядок обязательных работ. При отсутствии поля используется порядок работ конфигурации. Ручные сроки имеют приоритет перед таблицей. `null` означает отсутствие срока по правилам работы; пустая или неразобранная ячейка без ручного значения означает недоступные данные и случайный режим.

Путь к постоянной базе задаётся `QUEUE_DB_PATH`; по умолчанию `data/queue.sqlite3`. Каталог должен находиться на постоянном локальном диске/томе. Миграция применяется автоматически при первом использовании очереди.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /courses/{course}/groups/{group}/queue` | Текущая очередь до окончания +10 минут, затем список ближайшего будущего занятия |
| Тот же GET с `?session_id=...` | Конкретное занятие, включая зафиксированный состав |
| `POST /courses/{course}/groups/{group}/queue/attendance` | Изменение посещения до начала пары |
| `POST /admin/courses/{course}/groups/{group}/queue/sessions` | Создание ручного занятия, существующая административная сессия обязательна |

Посещение передаётся через существующие поля формы:

```json
{
  "surname": "Фамилия",
  "name": "Имя",
  "patronymic": "Отчество",
  "github": "github-login",
  "session_id": "lesson-identifier",
  "will_attend": true
}
```

Сервер сопоставляет ФИО и GitHub с допущенным участником группы. Идентификация остаётся такой же, как в существующей форме; подтверждённая OAuth-личность этим способом не устанавливается. Без допуска ответ запрещён. После начала пары изменение возвращает 409. До конца пары + 600 секунд студентский GET показывает текущую очередь только для просмотра; затем возвращает следующее занятие.

Для ручного занятия передаются `session_id`, `teacher_key`, `starts_at`, `ends_at`. Даты начала и конца должны содержать часовой пояс, например `2026-11-13T10:00:00+03:00`.

## Состояния списка

- `unconfirmed`: посещение не подтверждено; зачёркнутая строка, включая предварительное место без допуска.
- `attending`: студент ответил «Да»; обычная строка с позицией среди приходящих.
- `declined`: явное «Нет»; зачёркнутая строка.

`position=null` означает, что студент не включён в состав приходящих. Интерфейс показывает предварительную строку во время проверки. Параметр `preview_lab` запрашивает оценку позиции при известных сроках; он не создаёт участника и не резервирует место.

Состав начавшегося занятия сохраняется событием `roster_frozen`. Обновление допуска в таблице не удаляет строки из этого снимка. Принадлежность к группе, состояние посещения и случайные ключи хранятся в SQLite. При работе случайного режима перезагрузка страницы не перемешивает список.

## Связь с существующей проверкой

После записи результата в Google Sheets запускается синхронизация очереди. Для уже защищённых/допущенных ячеек используется чтение таблицы; повторная запись оценки не требуется. Сбой синхронизации не отменяет успешно сохранённый результат проверки. Чтение страницы очереди повторяет синхронизацию с кэшем 15 секунд на группу.

Сетевая ошибка при наличии предыдущего успешного чтения позволяет вернуть список с `stale=true`; изменение посещения на устаревших данных блокируется до восстановления чтения. Постоянный снимок чтения хранится в SQLite и доступен после перезапуска. Отложенная сверка и административные действия подключены; подробности в [инструкции](RUNBOOK.md).

## Проверка

Чистые модули, реальная временная SQLite-база и искусственная таблица проверяются unit-тестами. Синтаксис `main.py` проверен отдельно. HTTP-тесты FastAPI с временной SQLite-базой и искусственной таблицей проходят в текущем окружении. Чтение реальной Google-таблицы этим прогоном не проверяется; для этого нужен собственный тестовый курс по `docs/DEVELOPMENT.md`.


## Панель преподавателя

Для маршрутов ниже сервер требует существующую cookie `admin_session`.

| Метод и путь | Действие |
|---|---|
| `GET /admin/queue/sessions` | Занятия всех курсов и групп, до 500 записей |
| `GET /admin/courses/{c}/groups/{g}/queue?session_id=...` | Полный состав, попытки, все вызванные/следующий, статистика и последние 200 событий |
| `POST /admin/courses/{c}/groups/{g}/queue/actions` | Вызов, результат, ручной хвост, удаление, закрытие/открытие записи |
| `GET /admin/courses/{c}/queue/settings` | Настройки и список работ; с `group_id` также текущий режим и блокировка |
| `PUT /admin/courses/{c}/queue/settings` | Сохранение `random` и словаря `deadlines` |
| `PATCH /admin/courses/{c}/groups/{g}/queue/sessions/{s}` | Перенос с `starts_at` (окончание +90 минут), отмена с `cancel: true` или восстановление с `restore: true` |
| `PUT /admin/courses/{c}/groups/{g}/queue/schedule` | Сохранение объекта `config` расписания группы |
| `POST /admin/courses/{c}/groups/{g}/queue/schedule/refresh` | Обновление занятий из сохранённого источника |

Тело действия:

```json
{"session_id":"lesson-identifier","action":"result","entry_id":123,"outcome":"defended"}
```

`action`: `call_next`, `result`, `correct_result` (нужны `entry_id`, `outcome`), `add_tail` (нужен `candidate_id`), `withdraw` (нужен `entry_id`), `close_enrollment`, `open_enrollment`. Результаты: `defended`, `failed`, `no_show`. Закрытие и открытие записи работают до начала пары. Для продолжения приёма вне расписания преподаватель создаёт ручное занятие.

Запрос настроек содержит полный набор ручных переопределений сроков. Отсутствие ключа означает чтение из таблицы, `null` означает работу без срока. После сохранения эти настройки заменяют переопределения из YAML, а не дополняют их. Настройка расписания сама по себе не меняет режим и сроки.

Конфликт состояния или времени возвращает 409, неверные параметры 422, ошибка внешнего чтения 502, изменение посещения на устаревшем допуске 503. Преподаватель может управлять сохранённым составом при `stale=true`; студент не может менять посещение до восстановления чтения.

Список маршрутов относится к включённой функции `queue.enabled`; курс без неё возвращает 404 на маршрутах очереди. [Форматы расписания и запуск](RUNBOOK.md).


### Параллельные защиты

Ответ панели содержит `current_entry_ids` (массив всех вызванных) и `next_entry_id`. Поле `current_entry_id` сохранено для совместимости и указывает первого вызванного, но не ограничивает число защит. `call_next` вызывает ещё одного ожидающего. Для безопасного повтора HTTP-команды передаётся `request_id`: повтор того же ID в рамках занятия и преподавателя не вызывает следующего второй раз. `result` принимает `entry_id` конкретной защиты.

Интерфейс очереди поддерживает ru/en/zh; язык сохраняется в существующей настройке браузера. Даты показываются с учётом языка и часового пояса занятия. Расширение расписания и поправки курса описаны в [COURSE_CONFIG.md](../../../COURSE_CONFIG.md#расписание-очереди-и-поправки-курса).


### Две сверки после занятия

В ответе преподавателя `service_ends_at` задаёт местную полночь, `service_open` показывает доступность вызова и результата. `reconciliation.checked_at` хранит время ранней сверки без закрытия ожидающих; `due_at` после неё указывает ночное чтение. `done_at` означает завершение финальной сверки. При ошибке `due_at` переносится на минуту, поля сохраняются в SQLite. Независимо от фоновой задержки после `service_ends_at` вызов и новый результат получают 409. Новых записей в закончившееся занятие эта доработка не открывает.


### Отмена и восстановление

`PATCH /admin/courses/{c}/groups/{g}/queue/sessions/{session_id}` принимает одно действие: `{ "cancel": true }`, `{ "restore": true }` либо пару дат для переноса. Смешивать действия в одном запросе нельзя. Повтор отмены/восстановления не создаёт повторного события.

Список занятий возвращает `service_started`, `can_move`, `can_cancel`, `can_restore`. Состоявшиеся защиты препятствуют переносу даже после отмены. Восстановление сохраняет идентификатор занятия, повышает ревизию и записывает событие `restored`; состав начавшегося занятия остаётся прежним. Конфликт активной попытки другого занятия возвращает 409 без частичного восстановления.


### Совместимость прежнего представления и команд

`entries` содержит одну строку на студента, с первой доступной работой после последней защищённой или её предварительным местом. В интерфейсе кругов преподаватель добавляет следующую допущенную работу вручную в конец; неудачная защита может создавать автоповтор. Подтверждение участия относится к занятию и сохраняется при смене работы. `can_add_tail` разрешает кнопку только для подтвердившего участие студента с текущим допуском и без активной попытки. Сервер проверяет подтверждение независимо от интерфейса.

`last_result` содержит последнюю завершённую попытку для исправления. `correct_result` меняет любой из трёх результатов, сохраняет событие с прежним и новым результатом, снимает ещё не вызванные зависимые попытки и при необходимости создаёт повторную. Если следующая попытка уже началась, возвращается 409. Подтверждённую таблицей защиту сначала требуется исправить в самой таблице; очередь Google Sheets не изменяет.

В событиях `attempt_number` — порядковая фактическая попытка данного студента по данной работе на выбранном занятии. Ожидание, которое отменено до вызова, номера попытки не получает. `entry_id` остаётся техническим идентификатором записи. `result_corrected` возвращает также `previous_outcome` и `outcome`.

Предварительный приоритет считается относительно текущей недели. При начале занятия порядок и приоритет фиксируются. Перенос через PATCH разрешён только на будущее время; переданный старым клиентом `ends_at` не меняет длительность 90 минут.


### Текущая панель: круги и отмена

Панель использует `round_entries`, `absent_entries`, `student_catalog`, `preferences`. Массив `entries` оставлен для совместимости; текущая таблица по кругам строится из отдельных попыток `round_entries`, включая завершённые. Активная попытка по предмету остаётся единственной. Записи, отменённые через журнал, имеют `voided_at` и не выводятся.

Новые `action` в прежнем `/actions`: `call`, `uncall`, `pass`, `fail`, `absent` с `entry_id`; `arrived`, `add_student` с `student_id`; `undo` с `command_id`. Для новых команд нужен уникальный `request_id`. Успешный ответ содержит `undo.command_id`, `expires_at`, `remaining_ms`; время повторного запроса не продлевает старое окно. Сервер хранит снимок изменений и восстанавливает его атомарно, сохраняя события истории. При конфликте или истечении срока возвращается 409.

`PUT /admin/courses/{course}/queue/preferences`: `{"auto_repeat":true,"undo_seconds":5}`. Настройки общие для предмета. `undo_seconds` — целое от 1 до 10, некорректное значение даёт 422. GET настроек возвращает `preferences` независимо от наличия расписания. Начальные значения: автоповтор включён, отмена 5 секунд.

В новых командах ручное добавление и возврат отсутствующего не требуют прежнего подтверждения студента: их разрешает преподаватель. Защищённая строка остаётся в первом списке; следующая допущенная работа добавляется вручную. Если такой работы нет, допускается ручной повтор завершённой защиты этого занятия. Прежние `call_next/result/add_tail/correct_result` сохранены для совместимости и не являются элементами нового интерфейса.


### Студенческий режим текущего занятия

В период `starts_at <= now < ends_at + 600` публичный GET возвращает `read_only: true`, `attendance_open: false`, `enrollment_opens_at`, публичные `round_entries` и `absent_entries`. Порядок и статусы совпадают с панелью преподавателя, но `history`, каталог студентов, идентификаторы команд и прочие данные управления не возвращаются. Явный запрос будущего занятия не открывает запись в обход окна. POST посещения до окончания текущей пары +10 минут возвращает 409, даже с идентификатором будущей пары. Ровно на границе запись снова разрешена, если есть подходящее будущее занятие.


## Предварительный состав группы

В будущих списках `entries` включает `student_id`, `ready`, `virtual_priority` и `roster_order`. При `ready=false` у студента ещё нет допуска для выбранной цели; `candidate_id` отрицательный и не является ключом допуска. Отправлять его в команды защиты нельзя. `github` может быть пустым, если студент ещё не зарегистрировался. В случайном режиме список включает всю группу; в режиме −1 завершившие все работы исключены. Случайный ключ хранится отдельно на занятие и не меняется после регистрации.
