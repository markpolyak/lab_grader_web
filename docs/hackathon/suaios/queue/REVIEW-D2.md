# D2: дополнительный FIFO

## D2/D3 — дополнительный FIFO

Преподаватель открывает «Дедлайны и порядок», включает «FIFO — по времени записи», задаёт «Открывать запись за, минут» и сохраняет настройки. По умолчанию 15 минут; допустимы целые 0–1440. Чекбоксы FIFO и случайного порядка взаимоисключающие. FIFO не требует дедлайнов. При отключённых чекбоксах сохраняется приоритет −1, а при недоступных дедлайнах — прежний случайный режим.

Сохранённые параметры API `PUT /admin/courses/{course}/queue/settings`:

```json
{"random": false, "fifo": true, "opens_before_minutes": 15, "deadlines": {}}
```

В FIFO до `starts_at - opens_before_minutes*60` кнопок подтверждения нет, а сервер отклоняет запись. На нижней границе запись разрешена и продолжается строго до `ends_at`. Порядок — по последовательности подтверждений «Приду», сохранённой событиями БД. Повтор того же ответа не меняет место. «Не приду», затем новое «Приду» — новое место в конце. При равной секунде время принятия команд различается порядком событий. Уже вызванный студент снимается через преподавателя; ожидающий может отказаться самостоятельно.

В остальных моделях сохранено прежнее подтверждение до начала занятия. Поэтому добавление FIFO исправляет D2/D3 в выбранном FIFO, но не означает, что все старые режимы приведены к исходному требованию. Переименование публичного раздела в «Предварительная очередь» — уточнение интерфейса, не доказательство исправления D3.


D3 и D6 покрываются этим же механизмом: нижняя граница запрещает раннюю запись, верхняя допускает самостоятельную запись до конца пары. В ответах на эти ветки указывается один пакет D2; самостоятельное опровержение факта прежнего поведения не заявляется. Регрессионные тесты: `tests/test_queue_review_fifo.py`, `test_review_fifo_settings_window_and_running_signup` в `tests/test_queue_endpoints.py`.
