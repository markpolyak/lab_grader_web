# Очередь на защиту лабораторных — sensei-mcp

Решение для #62: очередь занятия со студенческой записью, управлением
преподавателя, автоматическим окном регистрации, файловым состоянием и историей.
Очередь встроена в существующие FastAPI/React и Google Sheets, без нового
отдельно разворачиваемого сервиса.

## Команда

**sensei-mcp:** @Weit145 @M1sterius @KorolevskiiKorol @colosss.
[Регистрация](https://github.com/markpolyak/lab_grader_web/issues/64#issuecomment-6561465266).

## Реализовано

- HTTP-команды join/leave, позиция, проверка группы и успешной проверки лабы
  по Sheets (`v`, штрафы и баллы); одна активная запись студента в пределах курса.
- Вызов нескольких студентов одновременно, завершение/неявка, исправление
  результата и терминальные состояния finished/withdrawn/expired.
- Автоокно записи для занятий: по умолчанию за 15 минут до пары и до её конца;
  ручное открытие/закрытие, обслуживание ожидающих до конца московского дня.
- Фоновая сверка времени, в том числе без Google-истории; сохранение состояния
  в YAML, восстановление после рестарта и истечение старых записей.
- При переносе расписания занятая старая очередь остаётся доступна преподавателю;
  новая запись идёт по актуальному занятию.
- Ручные занятия, перенос/отмена через admin API, постоянные Docker-тома.
- Локальная история хранит результаты и время завершения после архивации;
  дополнительная Google-выгрузка содержит список участников.
- Сериализация команд и атомарная запись YAML; rollback при отказе записи;
  защита read/validate/write конфигураций, атомарный индекс и проверка устаревших
  правок в редакторе курса.
- Страницы занятий/очереди/admin, переводы ru/en/zh, WebSocket-уведомления и polling.

## Принятые допущения

1. Область уникальности активной записи — **курс**. Разные курсы независимы.
2. Самостоятельный выход разрешён только ожидающему; вызванную запись завершает
   преподаватель. Приоритетов нет, повторная запись идёт в конец.
3. Ручной режим регистрации имеет приоритет над автоматическим окном для занятия.
4. День обслуживания заканчивается по Europe/Moscow. Явный service_until может
   заменить границу; явное завершение занятия переводит остаток в expired.
5. Один backend-worker/экземпляр сервиса. Межпроцессная запись файлов не поддержана.
6. Каноническая история результатов — локальные YAML и admin API; Google-экспорт
   не заменяет её backup и не записывает результат в существующие ячейки оценок.
7. Полная история хранится без автоматического retention; каталоги данных
   должны находиться на постоянном томе.

| Файлы | Назначение |
| --- | --- |

## Известные ограничения

- Провайдер парсера расширяемый, но чтение/генерация QueueService пока привязаны
  к SUAI. Полный ручной источник в конфигурации курса, queue.enabled,
  настройка lead time на курс и дневной режим без расписания не завершены.
- Выход студента, выбор «защитил / не защитил» и просмотр истории доступны
  в API, но не полностью доведены до UI; открытый список занятий не обновляет
  доступность по таймеру.
- Между неудачными попытками архивации archive_requested проверяется не всеми
  путями reconcile/delete. Непосредственное сохранение снимка блокируется.
- Подтверждённая сессия студента в queue API и ограничение публичных данных
  участников не реализованы. Это ограничение, не согласованное исключение
  из требований заказчика.
- В frontend dependency tree известны advisory; текущий npm audit отмечает
  12 пакетов (1 critical, 8 high, 3 moderate). Применимость зависит от browser/
  Node/build пути; эксплуатация именно этой сборки не доказана.
- Реальные Google Sheets/сайт ГУАП и визуальная мобильная проверка не входили
  в последний автоматизированный прогон. Возможность подделки admin cookie
  при публичном SECRET_KEY по умолчанию остаётся конфигурационным риском.
