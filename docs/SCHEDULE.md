# Расписание преподавателей

`queues/parser/parser.py` содержит `ScheduleParser` и `ScheduleConfig`.
Расписание сохраняется в `schedule/<university>/<semester>/<teacher>.yaml`.
Обязательный код университета выбирает источник; сейчас поддерживается `suai`.
ФИО используется для поиска единственного преподавателя по подстроке без учёта
регистра. Если совпадений нет или несколько, сохранённый файл не заменяется.

Настройки в `schedule/index.yaml`:

```yaml
schedules:
  - university: suai
    teacher: "Фамилия И.О."
    semester:
      id: "2026-autumn"
      starts-on: "2026-09-01"
      ends-on: "2026-12-31"
      first-week-start: "2026-08-31"
    timezone: Europe/Moscow
    refresh-interval-days: 7
```

По умолчанию в index.yaml настроен Поляк Марк Дмитриевич с `semester: auto`.
Полное ФИО преобразуется в фамилию с инициалами для поиска на сайте.
В автоматическом режиме семестр и учебный год берутся с сайта ГУАП, первая
неделя рассчитывается по опубликованной текущей дате и номеру недели.
Окончание рассчитывается по `teaching-weeks` (по умолчанию 18), поскольку
источник не публикует точную дату окончания; в YAML стоит `end-estimated: true`.
При устаревшей дате источника или номере недели вне учебного периода обновление
отклоняется, старые файлы сохраняются. Новый семестр получает отдельный каталог.
Если `semester` отсутствует, также используется автоматический режим.

Для точных границ можно задать даты вручную, как в примере выше.
`first-week-start` — понедельник первой
учебной недели; она считается нечётной. Праздники и разовые отмены этот
повторяющийся шаблон автоматически не учитывает.

FastAPI lifespan запускает BackgroundScheduler APScheduler 3.x. При старте,
затем каждый час проверяется срок последней успешной загрузки. Загрузка
выполняется только если файла нет, настройки изменились или истёк интервал
(по умолчанию 7 дней). После ошибки повторная попытка — при следующей часовой
проверке. HTTP-кэш внешнего парсера при обновлении игнорируется.
Работа выполняется в потоке, не блокируя WebSocket. Запускайте один процесс
backend, иначе каждый процесс запустит собственный планировщик.

В YAML `days` содержит ключи ISO-дат, списки занятий включают `subject`, `kind`,
`starts-at`, `ends-at`, `groups`, `room`. Даты без занятий отсутствуют.
Занятия вне сетки сохраняются в `unscheduled` без выдуманного времени.
ID преподавателя и занятия в выходном файле не создаются.

При успешной проверке обновляется `last-checked-at`; `updated-at` меняется
только вместе с содержимым. Порядок занятий стабилен, дубли удаляются.
Прошедшие сохранённые даты остаются прежними при неизменных настройках.
При ошибке сети/парсинга или пустом ответе старый YAML сохраняется. Файл
заменяется атомарно. Это история опубликованного расписания, не посещений.

`SCHEDULE_DIR` меняет каталог выгрузок, `SCHEDULE_CONFIG` — путь конфигурации.
В production смонтируйте постоянный каталог на `/app/schedule` с правами записи
пользователя контейнера. В development каталог уже доступен через bind mount.

Можно выполнить ручное обновление (из корня проекта):

```python
from queues.parser.parser import ScheduleParser

parser = ScheduleParser()
for config in parser.load_configs("schedule/index.yaml"):
    parser.refresh(config, force=True)
```

Модули upstream закреплены на конкретном коммите; источник описан в
`queues/parser/vendor/SOURCE.md`. Парсер сохраняет YAML; объекты занятий и очередей
из этой выгрузки создаёт отдельный `QueueService`.

## Занятия и очереди курса

`queues/usecase/queue_service.py` использует доменные классы `Schedule`, `Lesson`
и `Queue`, без `QueueRecord`. В `service.schedules` ключ — стабильный ID курса.
У `Schedule` есть `course_id`, `course_name`, `week_start`, `lessons`.
`course_name` точно сопоставляется с `subject` из YAML. Сейчас включаются только
активные курсы ГУАП; архив и ИТМО пропускаются. Все типы занятий, включая лекции,
получают отдельную очередь. Если нужна очередь только на лабораторных, это
отдельное правило фильтрации, которого сейчас нет.

У `Lesson` есть `id`, `starts_at`, `ends_at` (datetime с часовым поясом),
`groups`, `kind`, `room` и одна собственная `queue`. Занятие для нескольких групп
создаёт одну общую очередь этого занятия. Занятия из `unscheduled` не включаются:
без конкретного времени начало очереди определить нельзя.

Понедельник нужной недели передаётся как `week_start`; по умолчанию это текущая
неделя в Europe/Moscow. На сервере экземпляр доступен как
`app.state.queue_service`: сохранённые YAML загружаются при старте, затем после
каждой фоновой проверки расписания. Независимая задача APScheduler
`queue-schedule-sync` перечитывает локальные YAML каждую минуту, включая
понедельник 00:00 по Москве. Это подхватывает ручные изменения файлов и
переключает неделю без запросов пользователей, даже когда `schedules: []`
отключает сетевой парсинг. Обновления сериализованы общей блокировкой сервиса.
При ошибке YAML прежние расписания и очереди остаются в памяти; задача повторяет
попытку через минуту. Если ошибка есть уже при старте, приложение запускается
и ждёт исправления файла или успешного парсинга.
`QUEUE_WEEK_START=2026-11-09` фиксирует неделю для разработки; удалите переменную,
чтобы вернуться к текущей неделе.

Повторная загрузка того же занятия сохраняет его Queue, записи и ручное
состояние `closed`. Изменение аудитории не создаёт новую очередь. Другая дата,
время, группа или тип занятия создают другое занятие с новой пустой очередью.
Занятия прошлых недель и убранные из расписания занятия остаются во внутреннем
кэше `_lessons` до остановки процесса, вместе с участниками и состоянием очередей;
при повторном появлении используется их прежняя очередь. Это ещё не постоянная
история: после перезапуска процесса записи и старые очереди теряются. Из YAML
восстанавливаются занятия текущей недели с пустыми очередями. Запись в Google
Sheets и удаление из памяти не выполняются. Новые очереди закрыты,
как предусматривает существующий класс Queue. Автоматическое открытие по времени
и команды записи/вызова в этом изменении не реализуются.

## Тестовые данные без Google Sheets и сети

В репозитории уже есть выгрузка Поляка за осень 2026 года. Из корня проекта:

```bash
.venv/bin/python scripts/queue-demo.py --week-start 2026-11-09
```

Команда создаёт отдельный QueueService, загружает неделю и выводит JSON: для
`os-2026` — четыре занятия (три лабораторных и лекция), у каждого пустая очередь.
Можно передать собственный каталог с той же структурой
`--schedule-dir /путь/к/данным` и конфигурации `--courses-dir /путь/к/курсам`.

Для работы с объектами в интерактивном Python:

```bash
.venv/bin/python -i scripts/queue-demo.py --week-start 2026-11-09
```

После вывода расписания доступна переменная `service`:

```python
from queues.domain.student import Student

schedule = service.schedules["os-2026"]
lesson = schedule.lessons[0]
lesson.queue.closed = False
student = Student("Иван", "Иванов", "Иванович", "test-student")
entry = lesson.queue.add_entry(student, lab_id="1", lab_name="ЛР1")
lesson.queue.get_position(github="test-student")  # 1
```

Этот сеанс не меняет состояние запущенного backend и не записывает тестового
студента на диск. Для загрузки той же недели непосредственно в backend задайте
в `.env` и перезапустите его:

```dotenv
QUEUE_WEEK_START=2026-11-09
SCHEDULE_CONFIG=schedule/offline.yaml
```

Второй параметр отключает запросы к сайту вуза; локальные выгрузки по-прежнему
читаются. Верните `SCHEDULE_CONFIG=schedule/index.yaml` для фонового обновления.
При Docker-запуске после обновления кода:

```bash
docker compose up -d --build backend
```

## HTTP: занятия курса на текущую неделю

`GET /courses/{course_id}/lessons` возвращает занятия из QueueService без
обращений к Google Sheets или сайту вуза. На frontend через nginx путь имеет
вид `/api/v1/courses/{course_id}/lessons`. Вход не требуется, данные студентов
в ответ не включаются.

```bash
curl http://localhost:8000/courses/os-2026/lessons
# Тот же запрос через frontend nginx:
curl http://localhost:8080/api/v1/courses/os-2026/lessons
```

Формат ответа (массив `lessons` сокращён до одного занятия):

```json
{
  "course_id": "os-2026",
  "course_name": "Операционные системы",
  "week_start": "2026-11-09",
  "week_end": "2026-11-15",
  "lessons": [
    {
      "id": "c15c88cc-4a05-5ebc-bd78-ae955277c0ef",
      "starts_at": "2026-11-09T15:10:00+03:00",
      "ends_at": "2026-11-09T16:40:00+03:00",
      "groups": ["4431"],
      "kind": "Лабораторное занятие",
      "room": "23-09 (Б. Морская 67)",
      "queue": {"closed": true, "entries_count": 0}
    }
  ]
}
```

`week_start` — понедельник, `week_end` — воскресенье включительно. По умолчанию
неделя определяется по текущему времени Europe/Moscow; `QUEUE_WEEK_START`
по-прежнему позволяет выбрать тестовую неделю. При смене недели эндпоинт
подгружает нужные даты из сохранённых YAML, не дожидаясь фоновой проверки.
Занятия отсортированы по времени, возвращаются все занятия недели, включая
прошедшие и занятия с закрытой очередью. `id` идентифицирует Lesson и связанную
с ним очередь; `queue.closed` — текущее состояние очереди, `entries_count` —
число её записей. Эндпоинт не открывает очереди автоматически и не определяет
личное право студента на запись. ФИО, GitHub-логины и сами записи не выдаются.

Если у настроенного курса нет занятий на этой неделе, ответ — `200` с
`lessons: []`. Для неизвестного курса или курса без настроенного расписания
очередей (включая ИТМО и архивные курсы) — `404`. Если QueueService не готов
или при смене недели не удалось прочитать выгрузки — `503`.

Схема также доступна в Swagger `/docs`. HTTP-команд записи и управления
очередью пока нет. `/ws` остаётся транспортом событий.

## Просмотр занятий на сайте

На главной странице выберите курс, затем «Запись в очередь». Откроется
`/course/{course_id}/queue` со списком занятий недели из указанного выше API:
название предмета, дата, время по Москве, группы, тип занятия и аудитория.
Кнопки «Выбрать» у занятий неактивны; запись в очередь ещё не подключена.
Отсутствие занятий и отсутствие настроенного расписания показываются разными
сообщениями. При ошибке загрузки можно повторить запрос.

Для проверки в Docker:

```bash
docker compose up -d --build
```

Откройте `http://localhost:8080`, выберите «Операционные системы» →
«Запись в очередь», либо сразу `http://localhost:8080/course/os-2026/queue`.
В сохранённой выгрузке есть занятия за осень 2026 года; для воспроизводимой
проверки вне этого периода используйте `QUEUE_WEEK_START=2026-11-09` и
`SCHEDULE_CONFIG=schedule/offline.yaml` в `.env`. Google Sheets не требуется.
