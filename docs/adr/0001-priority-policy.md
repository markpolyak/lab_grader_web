# ADR-0001. Приоритетная очередь с нижней границей −1

Команда выбрала очередь, в которой просроченные работы имеют приоритет −1, работы текущего дедлайна — 0, а будущие сроки — положительные значения. Просрочка не накапливает дополнительное преимущество. Решение принято с учётом доли оценок 3–5, сокращения нулевых результатов и распределения баллов перед экзаменом.

## Контекст

На занятии преподаватель успевает принять ограниченное число лабораторных. Приоритет должен учитывать срок работы, поддерживать устранение задолженности и оставаться понятным студентам. Для группы и курса сохраняется постоянная очередь; расписание определяет, на каком занятии будет обслуживаться её текущий состав.

В [исследовании](../../research/queue-study/README.md) сравниваются восемь моделей. Три финалиста: случайная очередь, граница 0 и граница −1. Основной количественный показатель — доля студентов с итоговыми оценками 3, 4 или 5. Дополнительно учитываются нулевые результаты и возможность добрать до положительной оценки на экзамене.

## Основания выбора −1

| Свойство | Основание |
|---|---|
| Высокий охват оценками 3–5 | В базовом парном эксперименте обе ограниченные очереди дают около 80,9%, существенно выше случайной |
| Меньше нулевых результатов | У −1 около 2,27% студентов с нулём баллов против 2,37% у 0 и 6,38% у случайного порядка |
| Возможность добрать на экзамене | При одинаковых +5 баллах распределение −1 даёт больше положительных итоговых оценок, чем 0; точные доли и интервалы приведены в исследовании |
| Раздельные классы сроков | Просрочка соответствует −1, текущая неделя дедлайна — 0, будущие сроки — положительным значениям |
| Ограниченная привилегия долга | Просрочка на десять недель не даёт преимущества перед просрочкой на одну неделю |

Снижение нулевых баллов является отдельным критерием результата. Нулевой балл не равнозначен отсутствию приёма: студент мог получить попытки, но не заработать баллы. Доля студентов без единой принятой попытки в базовом эксперименте финалистов равна нулю у всех трёх моделей.

Экзаменационный сценарий предполагает одинаковые дополнительные баллы для всех студентов. Он показывает свойства распределения, а не предсказывает результаты реального экзамена. Совокупность этих критериев служит основанием выбора −1.

## Расчёт приоритета

```text
delta_weeks = deadline_week - session_week
priority = max(-1, delta_weeks)
```

Номера учебных недель определяются в часовом поясе курса относительно `semester_week_anchor`: `1 + (local_date - anchor_date).days // 7`. Неделя занятия задаётся его началом. Внутри одной учебной недели приоритет одинаков; на следующей неделе работа с прошедшим дедлайном относится к −1.

| Срок работы | Приоритет |
|---|---:|
| Просрочена на 10 недель | −1 |
| Просрочена на 1 неделю | −1 |
| Дедлайн на текущей учебной неделе | 0 |
| До дедлайна 2 недели | 2 |
| До дедлайна 18 недель | 18 |

Точная дата дедлайна сохраняется. Штраф из ячейки Google Sheets и приоритет являются разными значениями: штраф мог быть зафиксирован при прохождении проверки. Приоритет определяется по сроку работы и неделе занятия.

При одинаковом приоритете используется сохранённый порядок студента в первоначальном составе занятия: `(priority, session_roster.ordinal)`. Регистрация новой работы не меняет уже выделенное место. В исследовании равные приоритеты случайны; стабильный порядок является выбранным правилом интерфейса. До начала пары изменение дедлайна пересчитывает предварительные приоритеты; после начала первоначальный состав фиксирован. Текущий вызванный студент сохраняет своё обслуживание до результата.

## Формирование очереди и посещение

Целевой работой становится первая допущенная лабораторная после последней защищённой в установленном порядке работ. Пустые, ошибочные и ещё не допущенные ячейки пропускаются. Все работы до последней защищённой больше не влияют на выбор и приоритет: `vv / пусто / v` и `v / vv / v` дают работу 3. Если готовых работ после границы нет, предварительный приоритет считается по следующей после защищённой работе; без защищённых работ — по первой. Предварительное место не является допуском к защите.

В случайном режиме новый список включает всю группу, даже студентов без готовых работ и уже завершивших все работы. Жеребьёвка сохраняется для занятия и не меняется при регистрации новой работы. В режиме −1 завершившие все работы исключаются из нового списка и считаются не приходящими. На каждое новое занятие участие по умолчанию не подтверждено.

Для ближайшего занятия отображается вопрос «Хотите прийти на это занятие?». По умолчанию посещение не подтверждено: участник показан зачёркнутым и не вызывается. Ответ «приду» включает его в состав; явный ответ «не приду» отображается зачёркиванием. До начала пары ответ можно изменить в обе стороны. При начале занятия фиксируется состав текущего приёма; во время пары и 10 минут после неё студент смотрит текущую очередь; затем может подтвердить следующее занятие.

Зачёркивание не означает удаление из постоянной очереди, отмену допуска или результат «не явился». Неявку и результаты указывает преподаватель. В списке остаются объяснимые состояния: допущен, придёт, не придёт, вызван, защитил, не защитил, не явился.

После успешной защиты целевой становится следующая доступная работа после границы защиты. В интерфейсе кругов преподаватель добавляет новую попытку вручную. Повторное обслуживание уже присутствующего студента в рамках текущего занятия ставится в общий конец независимо от приоритета. Оно является продолжением текущего приёма, а не новым подтверждением посещения после закрытия состава. Среди повторных попыток используется порядок их создания.

Перенос занятия сохраняет постоянную очередь. При переносе того же занятия сохраняется его идентификатор и связанные намерения посещения; до нового начала их снова можно менять. При отмене без новой даты обслуживание переносится на следующее доступное занятие той же группы и курса. История состоявшихся попыток остаётся привязана к исходному занятию.

## Альтернативы

| Модель | Причина выбора другого варианта |
|---|---|
| Случайная | В базовом сценарии меньше оценок 3–5 и больше нулевых результатов |
| Неограниченный приоритет | Старый долг продолжает повышать преимущество; нижняя граница ограничивает эту привилегию |
| Граница 0 | Смешивает текущий дедлайн с просрочкой; при сопоставимом охвате оценками 3–5 у −1 меньше нулей среди финалистов |
| Больше завершённых работ | Большая доля нулей у оставшихся студентов |
| Довести до тройки | После 25 баллов останавливает обслуживание; ограничивает учебный прогресс |
| Фамилии на «К» и нечётные номера | Привилегия не связана со сроком, допуском или результатом работы |

Политика доступна для разных предметов. Выбор вуза и источника расписания описан в [ADR-0003](0003-schedule-adapters.md); хранение очереди, намерений посещения и попыток — в [ADR-0002](0002-sqlite-storage.md).
