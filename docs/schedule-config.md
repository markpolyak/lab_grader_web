# Опции конфигурации расписания

Этот документ описывает все поддерживаемые опции в YAML конфигурации расписания курса.

Конфиг расписания хранится отдельно от конфига курса (см. `course-config.md`) в файле `schedules/{course-id}.yaml`, например `schedules/dev-course.yaml`. Редактировать его можно двумя способами:

- вручную, в любом редакторе;
- в админке, на странице «Расписание» (вкладка «Редактор расписания», есть валидация на лету), а также вкладками «Коррекции» и «Источник», которые меняют отдельные части этого же файла.

## Структура файла

```yaml
course-id: dev-course          # идентификатор курса
source: manual                 # источник расписания по умолчанию
timezone: UTC+3                # часовой пояс
auto_open_minutes_before: 30   # автооткрытие очереди (необязательно)
auto_close_minutes_after: 30   # автозакрытие очереди (необязательно)

manual-groups:                 # группы, добавленные вручную
  - "4431"
  - "4432"

groups:                        # расписание по группам
  "4431":
    group_id: "4431"
    source: guap
    guap_group_id: "4431"
    slots:
      - id: guap-mon-2
        # ...
    corrections:
      - id: cancel-2026-11-10
        # ...
```

Обязательные ключи верхнего уровня: `course-id`, `source`, `timezone`, `groups`, `manual-groups`. Остальные необязательны.

---

## Верхний уровень

### `course-id` (обязательно)
**Тип:** `string`
**Описание:** Идентификатор курса. Должен совпадать с идентификатором курса, к которому относится расписание (и с именем файла: `schedules/{course-id}.yaml`). Непустая строка.
**Пример:**
```yaml
course-id: dev-course
```

### `source` (обязательно)
**Тип:** `string` (`guap` | `manual`)
**Описание:** Источник расписания по умолчанию. Используется для групп, у которых не задан собственный `source`.

- `guap` - слоты группы загружаются с сайта ГУАП и обновляются кнопкой «Получить расписание». Все слоты такой группы при обновлении **перезаписываются**, ручные правки слотов будут потеряны. Для точечных изменений используйте `corrections`.
- `manual` - слоты не обновляются автоматически и редактируются только в YAML.

Неизвестное значение (например, `guapp`) даёт предупреждение в редакторе, но не блокирует сохранение. Лучше его исправить: поведение для такой группы не определено.
**Пример:**
```yaml
source: manual
```

### `timezone` (обязательно)
**Тип:** `string`
**Описание:** Часовой пояс, в котором заданы время слотов и даты. Формат `UTC+3`, `UTC-5`, `UTC+0`. Не строка или пустое значение даёт предупреждение.
**Пример:**
```yaml
timezone: UTC+3
```

### `manual-groups` (обязательно)
**Тип:** `list[string]`
**Описание:** Номера групп, добавленных вручную. Для автоматической загрузки используются только вкладки Google Sheets с числовыми названиями групп; если нужной группы там нет, её добавляют в этот список (кнопка «Добавить группу» в админке) и заполняют расписание вручную. Список можно оставить пустым: `manual-groups: []`, но ключ должен присутствовать.

Номера пишите в кавычках, чтобы YAML не превратил их в числа.
**Пример:**
```yaml
manual-groups:
  - "4431"
  - "4432"
```

### `auto_open_minutes_before`
**Тип:** `integer`
**Описание:** За сколько минут до начала слота автоматически открывается очередь на сдачу.
**Пример:**
```yaml
auto_open_minutes_before: 30   # очередь открывается за 30 минут до начала пары
```

### `auto_close_minutes_after`
**Тип:** `integer`
**Описание:** Через сколько минут после окончания слота автоматически закрывается очередь на сдачу.
**Пример:**
```yaml
auto_close_minutes_after: 30   # очередь закрывается через 30 минут после конца пары
```

> **Про стиль ключей.** Верхний уровень использует `kebab-case` (`course-id`, `manual-groups`), а часть ключей внутри групп и автоматика очереди - `snake_case` (`group_id`, `guap_group_id`, `auto_open_minutes_before`). Пишите ключи ровно так, как они указаны в этом документе: система не приводит регистр и разделители к единому виду.

## Секция `groups`

**Тип:** `mapping`
**Описание:** Расписание по группам. Ключ - номер группы (строка из одних цифр), значение - конфигурация группы. Группа может присутствовать в `groups`, даже если её нет в `manual-groups` (например, она загружена из Google Sheets).

**Требование к ключу:** только цифры (`^\d+$`). Всегда берите ключ в кавычки: `"4431"`.
**Пример:**
```yaml
groups:
  "4431":
    group_id: "4431"
    slots: []
  "4432":
    group_id: "4432"
    slots: []
```

### `group_id`
**Тип:** `string`
**Описание:** Номер группы. Должен совпадать с ключом, под которым группа записана в `groups` (`"4431"` → `group_id: "4431"`), иначе ошибка валидации.
**Пример:**
```yaml
"4431":
  group_id: "4431"
```

### `source`
**Тип:** `string` (`guap` | `manual`)
**По умолчанию:** значение `source` верхнего уровня
**Описание:** Источник расписания для этой группы. Переопределяет глобальный `source`. Смена источника в админке (вкладка «Источник») меняет это поле.

Что происходит при смене:

- `guap` → `manual`: текущие слоты сохраняются и становятся базой для ручного редактирования.
- `manual` → `guap`: слоты будут перезаписаны при следующем нажатии «Получить расписание».
**Пример:**
```yaml
"4431":
  source: guap
```

### `guap_group_id`
**Тип:** `string`
**По умолчанию:** номер группы (ключ в `groups`)
**Описание:** Код группы на сайте ГУАП. Нужен, когда он отличается от номера группы в курсе. Используется только при `source: guap`.
**Пример:**
```yaml
"4431":
  source: guap
  guap_group_id: "4431"
```

### `slots`
**Тип:** `list[dict]`
**Описание:** Список слотов (занятий) группы. Каждый слот - одно регулярное или разовое занятие, на которое студенты записываются в очередь. Подробности - в следующей секции.

### `corrections`
**Тип:** `list[dict]`
**Описание:** Коррекции расписания: разовые отмены и дополнительные занятия, не меняющие основные слоты. Подробности - в секции «Коррекции».

---

## Секция `slots`

Слоты группы. У слота должно быть ровно одно из двух: `recurrence` (повторяющееся занятие) или `date` (разовое).

### `id` (обязательно)
**Тип:** `string`
**Описание:** Идентификатор слота. Должен быть уникальным **в пределах группы**. На него ссылаются коррекции, поэтому после публикации его лучше не менять.

Слоты, созданные из ГУАП, получают идентификатор по схеме `guap-{день}-{номер пары}`, например `guap-mon-2` (понедельник, вторая пара). Для ручных слотов используйте любое понятное имя в том же духе (`manual-wed-3`, `extra-lab5`).
**Пример:**
```yaml
slots:
  - id: guap-mon-2
```

### `recurrence`
**Тип:** `dict`
**Описание:** Правило повторения для регулярного занятия. Взаимоисключающе с `date`.

#### `recurrence.day` (обязательно)
**Тип:** `string`
**Описание:** День недели. Допустимы полные и сокращённые английские названия в нижнем регистре: `monday`/`mon`, `tuesday`/`tue`, `wednesday`/`wed`, `thursday`/`thu`, `friday`/`fri`, `saturday`/`sat`, `sunday`/`sun`.

#### `recurrence.week`
**Тип:** `string` (`all` | `odd` | `even`)
**По умолчанию:** `all`
**Описание:** Чётность недели: каждая неделя, только нечётные или только чётные.
**Пример:**
```yaml
- id: guap-mon-2
  recurrence:
    day: monday
    week: all
```

### `date`
**Тип:** `string` (`YYYY-MM-DD`)
**Описание:** Дата разового занятия. Взаимоисключающе с `recurrence`.
**Пример:**
```yaml
- id: extra-lab5
  date: "2026-11-14"
  start: "10:00"
  end: "11:30"
```

### `start` (обязательно)
**Тип:** `string` (`HH:MM` или `HH:MM:SS`)
**Описание:** Время начала в часовом поясе `timezone`. 24-часовой формат.

### `end` (обязательно)
**Тип:** `string` (`HH:MM` или `HH:MM:SS`)
**Описание:** Время окончания. Должно быть строго позже `start`.

> **Всегда берите время в кавычки.** Значение без кавычек вроде `10:40:00` некоторые YAML-парсеры (в том числе PyYAML) читают как число в шестидесятеричной системе (`38400`), а не как строку. Автоматически сгенерированные файлы кавычат такие значения, как `'10:40:00'`; если пишете вручную, делайте так же.

**Типовая сетка пар ГУАП:**

| Пара | Начало | Конец |
|------|--------|-------|
| 1 | 09:00 | 10:30 |
| 2 | 10:40 | 12:10 |
| 3 | 13:00 | 14:30 |
| 4 | 14:40 | 16:10 |
| 5 | 16:20 | 17:50 |
| 6 | 18:00 | 19:30 |

### `subject`
**Тип:** `string`
**Описание:** Название дисциплины. Многострочные названия YAML сворачивает сам, как в слоте `guap-mon-3` в примере ниже.

### `room`
**Тип:** `string`
**Описание:** Аудитория и корпус, например `23-10 (Б. Морская 67)`.

### `teacher`
**Тип:** `string`
**По умолчанию:** пустая строка
**Описание:** Преподаватель. ГУАП часто не отдаёт это поле, и тогда оно остаётся `''`.

### `labs`
**Тип:** `list[string]` или `null`
**Описание:** Номера лабораторных работ, которые принимаются в этом слоте. `null` или отсутствие ключа - слот не ограничен конкретными лабами. Если ключ задан, значение должно быть списком или `null`, иначе ошибка валидации.
**Пример:**
```yaml
- id: extra-lab5
  date: "2026-11-14"
  start: "10:00"
  end: "11:30"
  labs: ["5", "6"]
```

## Коррекции (`corrections`)

Коррекция меняет расписание группы **на одну дату**: отменяет слот целиком, отменяет в слоте только отдельные лабы или добавляет дополнительное занятие. Основные слоты при этом не трогаются, поэтому коррекции не теряются при обновлении расписания из ГУАП.

### `id` (обязательно)
**Тип:** `string`
**Описание:** Идентификатор коррекции, уникальный в группе.

### `date` (обязательно)
**Тип:** `string` (`YYYY-MM-DD`)
**Описание:** Дата, на которую действует коррекция. Другие форматы (`10.11.2026`, `2026-11-1`) дают ошибку.

### `remove_slots`
**Тип:** `list[dict]`
**Описание:** Отмена занятий на эту дату. Каждый элемент ссылается на `id` существующего слота. Если дополнительно указан список `labs`, отменяются только эти лабораторные в слоте; без него отменяется слот целиком.

### `add_slots`
**Тип:** `list[dict]`
**Описание:** Дополнительные занятия на эту дату. Элемент описывается так же, как обычный слот (`id`, `start`, `end`, `subject`, `room`, `teacher`, при необходимости `labs`), но `date` брать не нужно, она наследуется от коррекции.

В админке коррекция создаётся одного из двух типов: «Отмена занятия» (`remove_slots`) или «Дополнительное занятие» (`add_slots`). В YAML ничто не мешает указать оба поля в одной коррекции.

**Пример:**
```yaml
corrections:
  - id: cancel-os-2026-11-10
    date: "2026-11-10"
    remove_slots:
      - id: guap-mon-4            # отменить пару целиком

  - id: cancel-labs-2026-11-17
    date: "2026-11-17"
    remove_slots:
      - id: guap-mon-4
        labs: ["3"]               # отменить только приём лабы 3

  - id: extra-2026-11-14
    date: "2026-11-14"
    add_slots:
      - id: extra-2026-11-14-1
        start: "10:00"
        end: "11:30"
        subject: Операционные системы
        room: 23-09 (Б. Морская 67)
        teacher: ''
```

## Валидация

Редактор в админке проверяет файл на лету и подсвечивает проблемы в гаттере. Ошибки блокируют кнопку «Сохранить», предупреждения - нет.

**Ошибки** (сохранение невозможно):

- файл не разбирается как YAML, либо верхний уровень не mapping;
- отсутствует любое из полей `course-id`, `source`, `timezone`, `groups`, `manual-groups`;
- `course-id` пустой или не строка;
- `groups` не mapping; `manual-groups` не список;
- ключ группы содержит не только цифры;
- `group_id` не совпадает с ключом группы;
- `slots` или `corrections` не список;
- у слота нет `id` или `id` повторяется в группе;
- у слота нет ни `date`, ни `recurrence`, либо есть оба сразу;
- `recurrence` не объект; неизвестный `recurrence.day`; `recurrence.week` не из `all`, `odd`, `even`;
- `start` / `end` не в формате `HH:MM` / `HH:MM:SS`; `end` не позже `start`;
- `labs` не список и не `null`;
- у коррекции нет `id` или `date`; `date` не в формате `YYYY-MM-DD`;
- `remove_slots` или `add_slots` не список.

**Предупреждения:**

- неизвестное значение `source` (глобально или в группе);
- `timezone` не строка.

Пустой файл ошибкой не считается, но без обязательных ключей система не сможет им воспользоваться.

## Полный пример конфигурации

```yaml
course-id: dev-course
source: manual
timezone: UTC+3
auto_open_minutes_before: 30
auto_close_minutes_after: 30

manual-groups:
  - "4431"
  - "4432"

groups:
  "4431":
    group_id: "4431"
    source: guap
    guap_group_id: "4431"
    slots:
      - id: guap-mon-4
        recurrence:
          day: monday
          week: all
        start: '14:40:00'
        end: '16:10:00'
        subject: Операционные системы
        room: 23-09 (Б. Морская 67)
        teacher: ''
      - id: guap-mon-3
        recurrence:
          day: monday
          week: all
        start: '13:00:00'
        end: '14:30:00'
        subject: Разработка и проектирование интеллектуальных программных средств машинного
          обучения
        room: 23-10 (Б. Морская 67)
        teacher: ''
      - id: guap-thu-1
        recurrence:
          day: thursday
          week: all
        start: '09:00:00'
        end: '10:30:00'
        subject: Основы программной инженерии
        room: 23-09 (Б. Морская 67)
        teacher: ''
    corrections:
      - id: cancel-os-2026-11-10
        date: "2026-11-10"
        remove_slots:
          - id: guap-mon-4

  "4432":
    group_id: "4432"
    source: manual
    slots:
      - id: guap-tue-3
        recurrence:
          day: tuesday
          week: all
        start: '13:00:00'
        end: '14:30:00'
        subject: Операционные системы
        room: 23-10 (Б. Морская 67)
        teacher: ''
      - id: extra-lab5
        date: "2026-11-14"
        start: '10:00'
        end: '11:30'
        subject: Операционные системы
        room: 23-09 (Б. Морская 67)
        teacher: ''
        labs: ["5"]
```

## Примечания

1. **Кодировка:** файл должен быть в UTF-8, кириллица в названиях допустима.
2. **Кавычки:** номера групп, время (`'10:40:00'`) и даты (`"2026-11-14"`) всегда берите в кавычки, иначе YAML может прочитать их как числа.
3. **Отступы:** используйте пробелы (по 2 на уровень), табуляция в YAML недопустима. Элементы списка внутри `slots` могут идти как с отступом, так и вровень с ключом: оба варианта валидны.
4. **Генерация из ГУАП:** при `source: guap` слоты группы пересоздаются при каждом обновлении. Автоматически созданный файл может отличаться от ручного форматом кавычек, но по смыслу идентичен.
5. **Перезапись из админки:** вкладка «Источник» перечитывает файл, меняет поля `source` и сохраняет его заново. После этого комментарии в YAML и ручное форматирование не сохраняются, так что не храните в файле важные пояснения в комментариях.
